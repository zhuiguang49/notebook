# 数据结构和算法笔记（C++语言）

## 一些语法的小提示

1. 我们应该避免使用 C 风格的强制类型转换，例如 `int n = (int)f`，因为 C++ 风格的类型转换会被编译器检查，而 C 风格的不会。

## `for`循环

`for(auto ...)`语法是C++11引入的范围基于`for`循环，用于简化遍历容器的代码

**基本语法**

```c++
for (auto element : container){
	//使用 element
}
//auto自动推断循环变量的类型
//element是循环变量，用于访问容器中的每个元素
//container是要遍历的容器，如数组,std::vector、std::list
```

## `std::string`类
>需要注意的是，这样的类与C语言风格的字符串不同，对于`std::string`类来说，不存在终止符的概念，因为`std::string`使用内部计数来跟踪长度


### 常见成员函数
1. `size()`

返回字符串的长度（字符数）
示例：`std::cout << str.size()`

2. `length（）`

与`size()`效果相同

3. `empty()`

判断字符串是否为空
示例：`std::cout << (str.empty() ? "Yes" : "No")`
`empty()`函数返回一个`bool`类型的值，如果字符串的长度为0，返回`true`，如果长度不为0，返回`false`

4. `at()`

访问字符串中指定位置的字符
示例：`std::cout << str.at(0)`
>其实这个函数和`operator[](array[0]这种)`函数类似，但是`operator[]`并不会检查索引是否越界，如果索引越界，会导致未定义行为，例如访问无效内存地址；而`at()`函数在访问字符串中的字符之前，会检查索引是否在合法范围内，如果越界，会抛出`std::out_of_range`异常

5. `substr()`

返回从指定位置开始的子字符串
示例：`std::string sub=str.substr(0,5)`
>第一个参数为起始位置，表示字符串从哪开始截取，第一个记为0；第二个参数表示子字符串的长度，如果省略的话就截取从起始位置开始直到字符串末尾的所有字符，比如`str.substr(7)`就截取从第7个字符开始的所有字符。该函数返回一个新的`std::string`对象，该对象包含从原始字符串中截取的子字符串。

6. `find()`

查找子字符串在字符串中位置
示例：`std::cout << str.find("sub") << std::endl`

- `find()`函数返回子字符串或字符在主字符串中首次出现的位置，如果是子字符串，那么就返回子字符串的第一个字符在主字符串中的位置；如果没有找到，就返回`std::string::npos`，这是一个特殊的值，表示未找到子字符串。它的值通常是`std::string`类型的最大索引值。

- 其次，`find()`函数其实可以有两个参数，比如`str.find("world",20)`表示从索引20开始查找子字符串`world`的位置

7. `rfind()`

从字符串末尾向前查找指定的字符串或字符的位置（从右向左），与`find()`函数不同的是从字符串末尾逆向搜索，但是返回的值仍然是子字符串的第一个字符在主字符串中的索引

8. `replace()`

替换字符串中的部分内容
示例：`str.replace(pos,length,"new_substring")`

`pos`是要替换的字符串的其实位置，`length`是要替换的字符串的长度（字符的数量），`"new_substring"`是用作替换的新字符序列（C风格字符串）

9. `append()`

在字符串末尾添加内容
示例：`str.append("more")`
`append()`函数的重载形式有挺多种：
- `std::string& append(size_t count,char ch)`
示例： 

  ```c++
  str.append(5,'.')
  ```

  即向字符串末尾添加5个点号`'.'`，第一个参数表示添加的字符的个数，第二个参数表示添加的字符

- `str.append(another_gretting,6,10)`从`another_greeting`的第6个字符开始，复制10个字符到当前字符串的末尾

- 使用C风格字符串进行追加
`str.append("new_string")`

- 使用`std::string`追加
`str.append(new_string)`

>注意，append方法以及上述我们讲的所有函数都是`std::string`类的，作用对象本就是`std::string`对象，因此不管我们是使用C风格字符串还是`std::string`对象进行追加，接受字符串始终都是一个`std::string`对象

10. `insert()`

在指定位置插入内容
示例：`str.insert(pos,"inserted")`

- 使用C风格字符串插入
`srt.insert(pos,"new_string")`

- 使用`std::string`插入
`str.insert(pos,new_string)`

- 插入重复字符
`str.insert(pos,num_chars,char)`其中`pos`代表插入的位置，`num_chars`代表插入的字符重复的次数，`char`代表插入的字符

11. `erase()`

删除指定位置的字符或子字符串
示例：`str.erase(pos,length)`表示删除从`pos`开始的`length`个字符，如果没有第二个参数，就删除从`pos`开始的所有字符，如果没有参数，也即`str.erase()`，就表示删除字符串中的所有内容

12. `data()`

返回指向字符数据的指针
示例：`const char* data = str.data()`、`char* ptr = str.data()`

13. `compare()`

比较两个字符串
示例：`int result = str.compare("other")`  这里其实就是将`str`字符串和`other`字符串比较
`compare()`函数返回一个整数值，其实也就是ASCII码相减
再举一个例子`result = str1.compare(0,5,str3,0,5)`，即比较`str1`和`str3`的前5个字符

14. `front()  back()`

返回指向字符串第一个/最后一个字符的引用

## 异常处理

异常处理机制允许我们在程序运行过程中检测并处理错误，从而提高代码的健壮性和可维护性。

### 异常处理的基本概念
1. 抛出异常(`throw`)
使用`throw`关键字可以抛出一个异常。异常可以是任何类型的对象，但通常是标准库中预定义的异常类（如`std::exception`及其派生类的实例）

2. 捕获异常(`try-catch`)
- 使用`try`块来包裹可能抛出异常的代码
- 使用`catch`块来捕获并处理异常

### 常见的异常类
C++标准库提供了一些常用的异常类，他们都继承自`std::exception`类，常见的异常类包括：
- `std::exception`：包括所有标准异常的基类
- `std::runtime_error`：用于运行时错误
- `std::logic_error`：用于逻辑错误
- `std::out_of_range`：用于索引超出范围的错误
- `std::invalid_argument`：用于无效参数的错误

## C++ vector容器
1. 创建vector

`std::vector<int> myVector;`
`std::vector<int> myVector(5)`创建一个包含5个整数的vector，每个值都为默认值
`std::vector<int> myVector(5,10)`创建一个包含5个整数的vector，每个值都为10
`std::vector<int> myVector = {1,2,3,4}`

2. 在末尾添加元素

使用`push_back`方法向vector中添加元素
`myVector.push_back(7)`将整数7添加到vector的末尾

3. 移除末尾的元素

使用`pop_back`方法移除vector的最后一个元素，`pop_pack`方法并不会返回被移除的值，只是简单地葱香两种删除该元素，并调整向量的大小

示例：
```c++
std::vector<int> numbers = {1,2,3,4,5};
if(!numbers.empty()){
	numbers.pop_back();
}
std::cout << "Vector after pop_back: ";
for (int num : numbers){
	std::cout << num << " ";
}
std::cout <<std::endl;

//这时输出的就是1 2 3 4 
```


3. 插入元素`insert()`

`insert()`方法允许我们在向量的任何位置插入一个或多个元素，它可以接受一个迭代器作为未知参数，制定插入的位置，并且可以插入单个元素或一个范围内的元素

- **插入单个元素：**
`myvector.insert(position,value);`其中`position`是`vec`中的一个迭代器，指向插入位置之前的元素，下面是一个例子
```c++
std::vector<int> myvector = {1,2,4,5};
auto pos = myvector.begin()+2;
myvector.insert(pos,3);
//pos指向的是myvector中的第三个位置，所以insert方法就把'3'插入在第三个位置，后面的几个数依次向后移动
//这时候myvector = {1,2,3,4,5}
```

- 插入多个元素

`myvector.insert(position, num_elements, value);`这里`num_elements`表示要插入的元素数量，`value`表示要插入的值

- 插入区间

`myvector.insert(position, first, last);`这里的`first`和`last`是迭代器，分别指向要插入元素的起始位置和结束位置（不包括结束位置本身），下面是一个具体的例子

```c++
std::vector<int> vec = {1,2,3,4,5,6};
std::vector<int> to_insert = {7,8,9};
auto pos = vec.begin() + 3;
vec.insert(pos, to_insert.begin(), to_insert.end());
//这时候vec={1,2,3,7,8,9,4,5,6}
```

`myVector.at(0)`

## C++容器类$\text{<map>}$

$\text{<map>}$是标准模板库（STL）的一部分，它提供了一种关联容器，用于储存键值对，map容器中的元素是按照键的顺序自动排序的（通常是升序）


### 特性
- **唯一性：** 每个键在map中只能出现一次
- **双向迭代器：** map提供了双向迭代器，可以向前和向后遍历元素

### 基本语法
```c++
#include <map>//包含头文件

//声明map容器：
std::map<key_type, value_type> myMap;
//key_type是键的类型  value_type是值的类型

//插入元素
myMap[key] = value;

//访问元素
value = myMap[key];

//遍历map
for(std::map<key_type, value_type>::iterator it = myMap.begin(); it != myMap.end(); ++it){
	std::cout << it->first << " => " << it->second << std::endl;
}


//一些进阶用法

//检查键是否存在
if(myMap.find(key) != myMap.end()){
	//键存在，没有找到键的话，find函数也会有返回值，其会返回myMap.end()，这是一个特殊的迭代器，表示容器中最后一个元素之后的位置
}

//删除元素
myMap.erase(key);

//情况map
myMap.clear()

//获取map的大小
size_t size = myMap.size()
```

## C++标准库<unordered_map>

C++中<unordered_map>是标准模板库（STL）的一部分，提供了一种基于哈希表的键值对容器，他与`std::map`的不同之处在于，unordered_map不保证元素的排序，但是通常提供更快的查找速度

### 语法
1. 声明语法
```c++
#include<unordered_map>
std::unordered_map<key_type, vlaue_type> map_name;
//这里key_type是键的类型，value_type是值的类型
```

2. 构造函数

```c++
//默认构造
std::unordered_map<int, std::string> myMap;

//构造并初始化
std::unordered_map<int, std::string> myMap = {{1, "one"}, {2, two}};

//构造并指定初始容量
std::unordered_map<int, std::string> myMap(10);

//构造并复制另一个 unordered_map
std::unordered_map<int, std::string> anotherMap = myMap;

```

3. 一些基本操作

```c++
//插入元素
myMap.insert({3, "three"});

//访问元素
std::string value = myMap[1]; //获取键为1的元素的值

//删除元素
myMap.erase(1); //删除键为1的元素

//查找元素
auto it = myMap.find(2)// 这个find函数会返回一个迭代器，该迭代器指向第一个匹配给定键的元素，如果找不到这样的元素，就会返回myMap.end()
    
if(it != myMap.end()){
	std::cout << "Found:" << it->second << std::endl; 
}
//it->second访问迭代器所指元素的值部分，在std::map和std::unordered_map中，每个元素都是一个std::pair<const Key, T>类型的对象，其中first成员保存键，second成员保存值

// 遍历有三种常用的遍历方式：遍历键值对、遍历键、遍历值（指对值进行操作或者输出）

for(auto kv:map){
	cout << kv.first << "->" << kv.second <<endl;
}
//上面这种就是遍历键值对

for(auto iter = map.begin(); iter != map.end(); iter++){
	cout << iter->first << "->" << iter->second <<endl;
}

```

>需要注意的是`unordered_map`并不保证元素的顺序，因此元素的迭代顺序可能在不同的运行中不同；与`std::map`相比，`unordered_map`在元素数量较少时可能占用更多的内存


## C++对象与类

1. 需要注意`this`指针的使用，在类内成员函数传递参数的时候可以用this接受形参的值

2. **静态成员的使用：**这点其实体现在有很多个类的实例的时候，我们可能希望对其进行计数，那么我们就可以定义静态成员变量，使用`static type variable`来定义这样的静态变量，而这样的静态变量意味着所有这个变量是被大家所共享的。还有一点需要注意的地方就是**我们不能把静态成员的初始化放置在类的定义中，但是可以在类的外部通过使用范围解析运算符 `::` 来重新声明静态变量从而对它进行初始化** 

3. 常量成员函数：意指在成员函数后面加上`const`，这意味着函数承诺不会改变类的任何非静态数据成员；并且编译器会对常量成员函数进行检查，如果在函数内部有任何试图修改类成员变量的操作，编译器将报错。
```c++
class Rectangle {
private:
    int width;
    int height;

public:
    Rectangle(int w, int h) : width(w), height(h) {}

    // 常量成员函数
    int area() const {
        return width * height;
    }

    // 非常量成员函数
    void resize(int newWidth, int newHeight) {
        width = newWidth;
        height = newHeight;
    }
};
```

4. 常量对象
常量对象指声明为`const`的对象，这类对象不允许被修改，其定义方式有以下两种`const ClassName obj`和`ClassName const obj`。需要注意的是，**常量对象只能调用常量成员函数**，因为非常量成员函数可能修改对象的状态。

### 拷贝构造函数

拷贝构造函数是一种特殊的构造函数，它的参数是一个同类型对象的引用，其用于创建一个新对象，使其成为另一个已存在对象的副本。拷贝构造函数的声明通常如下：
`ClassName(const ClassName& original);`这里`ClassName`是类的名称，`const ClassName& original`是要复制的对象的引用
这里的参数使用了`const`来修饰避免修改被拷贝对象

拷贝构造函数通常在以下几种情况下被调用：
1. **显式调用：**直接通过构造函数调用来创建一个对象的副本
2. **传递对象给函数：**当函数的参数是按值传递时，传入的对象需要复制一份
3. **从函数返回对象：**当函数返回一个对象时，需要复制一份返回
4. **使用标准容器或算法：**当使用标准容器（如`std::cover`、`std::list`等）或算法(如`std::sort`、`std::copy`等)时，通常需要复制对象

### 深度复制与浅复制

- **浅复制：**仅仅复制对象的成员变量的值，对于指针或引用类型，只会复制指针或引用本身
- **深度复制：**不仅要复制对象的成员变量的值，还要递归地复制所有的子对象或数据结构。其核心是让每个对象都拥有自己独立的资源，避免多个对象共享同一块内存

拷贝构造函数实现深度复制的基本步骤如下：
```c++
ClassName(const ClassName& other){
	//分配新资源
	this->data = new char[strlen(other.data) + 1];
	//复制内容
	strcpy(this->data, other.data);
}
```

### 重载运算符和重载函数

C++允许在同一作用域中的某个函数和运算符指定多个定义，分别称为函数重载和运算符重载，重载声明是指一个与之前已经在该作用域内生命过的函数或方法具有相同名称的声明，但是参数列表和定义（实现）不同

#### 运算符重载

重载的运算符是带有特殊名称的函数，函数名是由关键字`operator`和其后要重载的运算符构成的，和其他函数一样，重载运算符有一个返回类型和一个参数列表
`Box operator+(const Box&)`声明加法运算符用于把两个Box对象相加，返回最终的Box对象。大多数的重载运算符可以被定义为普通的非成员函数或定义成类成员函数。如果定义上面的函数为类的非成员函数，就需要为每次操作传递两个参数，也即`Box operator+(const Box&, const Box&);`

##### 赋值运算符

默认情况下，C++会为类生成一个默认的赋值运算符，该运算符会逐个成员地进行浅复制(shallow copy)，对于简单的类来说，这种方式通常是足够的。但是当类中包含动态分配的资源（如指针）时，默认的浅复制就会引发问题。赋值运算符是一个重载运算符，用于将一个对象的值赋给另一个已存在的对象

**下面我们给出一个实现深度拷贝的完整类：**

```c++
#include <iostream>
#include <cstring>

class MyClass{
private:
	char* data;
public:

	MyClass(const char* value = ""){
		data = new char[strlen(value) + 1];
		strcpy(data, value);
		std::cout << "Constructor called for: " << data << std::endl;
	}
	
	MyClass(const MyClass& other){
		data = new char[strlen(other.data) + 1];
		strcpy(data, other.data);
		std::cout << "Copy constructor called for: " << data << std::endl;
	}
	
	MyClass& operator=(const MyClass& other){
		if(this == &other){
			return *this;
		}
		
		delete []data;
		
		data = new char[strlen(other.data) + 1];
		strcpy(data, other.data);
		
		std::cout << "Assignment operator called for: " << data << std::endl;
		
		return *this;
    }
		
	void showData() const{
		std::cout << "Data: " << data << std::endl;
	}
		
	~MyClass(){
		delete[] data;
		std::cout << "Destructor called for: " << data << std::endl;
	}
};
```

**赋值运算符的签名：**

```c++
ClassName& operator=(const ClassName& other);
```
返回类型：`ClassName&` 返回当前对象的引用，已支持连续赋值
参数：`const ClassName&` 通过常量引用传递参数，避免拷贝，提高效率

实现复制运算符的基本步骤如下：
1. **自我赋值检查：** 避免对象给自己赋值
2. **释放旧资源：** 清理当前对象中已有的资源，避免资源泄露
3. **深度复制资源：** 为当前对象分配新资源，并复制`other`对象的内容
4. **返回当前对象的引用：** 支持连续赋值

### 链表中添加结点

下面是一个链表节点结构的示意：
```c++
struct Node{
	int data;
	Node* next;
}
```


1. 在链表头部插入节点
- 创建新节点，并将其`next`指针设置为当前的头结点
- 将新节点赋值给头指针，使它成为新的头结点

```c++
Node* insertbefore(Node* head, int data){
	Node* newNode = new Node;
	newNode->data = data;
	newNode->next = head;
	
	return newNode;
}
```

2. 在链表特定位置插入节点
- 寻找要插入位置的前一个节点
- 新节点的`next`指针指向当前要插入位置的新节点
- 修改前一节点的`next`指针，使其指向新节点

```c++
//注意这里head是指向链表的头指针
Node* insertAfter(Node* head;Node *prevNode,int data){
	if(prevNode == nullptr){
		std::cout <<"Previous node cannot be full" << std::endl;
		return head;
	}
	Node* newNode = new Node;
	newNode->data = data;
	newNode->next = prevNode->next;
	prevNode->next = newNode;
	
	return head;
	
}
```

3. 在链表尾部插入节点
- 如果知道尾结点，则创建新节点并设置其`next`指针为`None`，然后将尾结点的`next`指针指向新节点
- 如果不知道尾结点，需要先遍历整个链表直到找到尾结点，然后执行上述操作

```c++
Node* insertAtTail(Node* head,int data){
	Node* newNode = new Node;
	newNode->data = data;
	newNode->next = nullptr;
	
	//如果链表为空，直接返回新节点作为头结点
	if(head == nullptr){
		return newNode;
	}
	
	Node* last = head;
	while (last->next != nullptr){
		last = last->next;
	}
	
	last->next = newNode;
	
	return head;
}
```

### 链表中删除节点

1. 删除头结点

```c++
	Node* deleteHead(Node*head){
		if(head == nullptr){
			return;
		}
		Node* temp = head //这里是为了保存当前头结点以便之后释放，避免内存泄漏
		head = head->next;
		delete temp;
		return head;
	}
```

2. 删除特定节点（非头结点）
- 定位要删除的节点
- 改变前一个节点，使它绕过删除节点
- 调用delete收回删除节点占用的内存空间
>需要注意的是，这里我们需要使用`prev`指针来指向前一个节点，因为我们第二步需要改变前一个节点的`next`指针的指向，所以我们得把它记录下来

```c++
Node* deleteNode(Node* head,int value){
	Node* current = head;
	Node* prev = nullptr;
	while(current != nullptr && current->value != value){
		prev = current;
		current = current->next;
	}
	if(current != nullptr){//也即找到了这样的节点
		prev->next = current->next;
		delete current;
	}
	else{
		std::cout <<"Element not found in the list." <<endl;
	}
	
}
```

## 栈(stack)

`<stack>`是C++标准模板库（STL）的一部分，实现了一个后进先出的数据结构，是基于其他容器（如`deque`和`vector`）来实现的，栈的元素是线性排列的，但只允许在一端（栈顶）进行添加和移除操作



### 基本操作

- `push()` 在栈顶添加一个元素
- `pop()` 移除栈顶元素
- `top()` 返回栈顶元素的引用，但不移除它
- `empty()` 检查栈是否为空
- `size()` 返回栈中元素的数量

### 基本语法
下面我们介绍一下`<stack>`的基本语法

```c++
#include <iostream>
#include <stack>

int main() {
    std::stack<int> s;

    // 向栈中添加元素
    s.push(1);
    s.push(2);
    s.push(3);

    // 访问栈顶元素
    std::cout << "Top element is: " << s.top() << std::endl;

    // 移除栈顶元素
    s.pop();
    std::cout << "After popping, top element is: " << s.top() << std::endl;

    // 检查栈是否为空
    if (!s.empty()) {
        std::cout << "Stack is not empty." << std::endl;
    }

    // 打印栈的大小
    std::cout << "Size of stack: " << s.size() << std::endl;

    return 0;
}
```

>需要注意的是：
>1. `<stack>`不提供直接访问栈中元素的方法，我们只能通过`top()`来访问栈顶元素
>2. 尝试在空栈上调用`top()`或`pop()`将导致未定义行为
>3. `stack()`的底层容器可以是任何支持随机访问迭代器的序列容器，如vector 或 deque
>

有基于链表和基于数组的两种实现

**时间效率：** 对于基于数组的实现：入栈操作和出栈操作都在预先分配好的连续内存中进行，具有很好的缓存本地性，效率高。但是当入栈时超出数组容量的话，就会触发扩容机制，导致该次入栈操作的时间复杂度变为$O(n)$；而对于基于链表的实现，由于链表的扩容非常灵活，不存在上述数组扩容时效率降低的问题。但是入栈操作需要初始化节点对象并修改指针，效率相对较低。当入栈与出栈操作的元素是基本数据类型时，我们可以得出以下结论：

- 基于数组实现的栈在触发扩容时效率会更低，但由于扩容时低频操作，因此平均效率更高
- 基于链表实现的栈则可以提供更加稳定的效率表现

**空间效率：**各有优缺，基于数组实现的栈，系统会为列表分派初始容量，这个容量可能超过实际需求；并且扩容时是按照特定倍率扩容的，也可能超出实际需求，因此基于数组实现的栈可能造成一定的空间浪费；而对于基于链表的栈，需要额外存储指针，其占用的空间相对较大

## 队列（queue）

C++ 标准库中的`<queue>`头文件提供了队列（`Queue`）数据结构的实现。队列是一种先进先出的数据结构，它允许在一端添加元素（称为队尾），并在另一端移除元素（称为队首）

### 队列的声明

```c++
#include <queue>
std::queue<Type> q;
//这里的Type是队列中存储元素的数据类型
```

### 常用操作
队列提供了一下常用操作：
- `empty()`检查队列是否为空
- `size()`返回队列中的元素数量
- `front()`返回队首元素的引用
- `back()`返回队尾元素的引用
- `push()`往队尾添加一个元素
- `pop()`移除队首元素

**下面是一个具体的实例**
```c++
#include <iostream>
#include <queue> 

int main() {
    // 创建一个整数队列
    std::queue<int> q;

    // 向队列中添加元素
    q.push(10);
    q.push(20);
    q.push(30);

    // 打印队列中的元素数量
    std::cout << "队列中的元素数量: " << q.size() << std::endl;

    // 打印队首元素
    std::cout << "队首元素: " << q.front() << std::endl;

    // 打印队尾元素
    std::cout << "队尾元素: " << q.back() << std::endl;

    // 移除队首元素
    q.pop();
    std::cout << "移除队首元素后，队首元素: " << q.front() << std::endl;

    // 再次打印队列中的元素数量
    std::cout << "队列中的元素数量: " << q.size() << std::endl;

    return 0;
}
```

**队列基于链表**的实现：可以将链表的“头节点”和“尾结点”分别视为“队首”和“队尾”，规定队尾仅可添加节点，队首仅可删除节点

**基于数组**的实现：在数组中删除首元素的时间复杂度为$O(n)$，这会导致出队操作效率较低。然而我们可以采用以下方法避免这个问题

可以使用一个变量`front`指向队首元素的索引，并维护一个`size`用于记录队列的长度，定义`rear = front + size`，这个公式计算出的`rear`用于指向队尾元素之后的下一个位置。而基于此设计，**数组中包含有效元素的区间为$[front, rear - 1]$**，对于入队操作，我们只需将输入元素赋值给`rear`索引处，并将`size`+1,；对于出队操作，我们只需将`front`+1，并将`size`-1。这样以后入队和出队操作都只需要进行一次操作，时间复杂度均为$O(1)$



## 双向队列(double-ended queue)

双向队列是提供了更高的灵活性，允许我们在头部和尾部执行元素的添加或删除操作。在C++中`<deque>`提供了双向队列的实现，`<deque>`是一个动态数组，它提供了快速的随机访问能力，同时允许在两端进行高效的插入和删除操作

### 双向队列的声明
```c++
#include <deque>

std::deque<int> myDeque;//这里创建了一个整数类型的双端队列
```

### 常用操作
- `push_front()` 将元素添加至队首
- `push_back()` 将元素添加至队尾
- `myDeque.front()` 访问myDeque的队首元素
- `myDeque.back()` 访问myDeque的队尾元素
- `myDeque.size()` 获取双向队列的长度
- `myDeque.empty()` 判断双向队列是否为空

## 优先队列(priority_queue)

优先队列是一种特殊的队列，它允许我们快速访问队列中具有最高（或最低）优先级的元素。在C++中，`priority_queue`默认是一个最大堆，也即优先级最高的元素在顶部（值最大），`priority_queue`是一个容器适配器，提供了对底层容器的对操作，但它既不提供迭代器，也不支持随机访问。



### 特点

- 默认情况下，有点队列是基于最大堆实现的，这意味着每次`top()`返回的是队列中优先级最高（值最大）的元素
- 可以通过提供比较器，构建最小堆或其他排序规则
- `std::priority_queue`是基于动态数组（如`ste::vector`）实现的堆结构

### 常用操作

- `empty()` 检查队列是否为空
- `size()` 返回队列中的元素数量
- `top()` 返回队列顶部的元素（不删除它）
- `push()` 向队列添加一个元素
- `pop()` 移除队列顶部的元素

最大堆示例：
```c++
#include <iostream>
#include <queue>
#include <vector>

int main() {
    std::priority_queue<int> pq;  // 默认最大堆

    pq.push(10);
    pq.push(30);
    pq.push(20);

    std::cout << "优先队列中的元素从大到小输出:\n";
    while (!pq.empty()) {
        std::cout << pq.top() << " ";  // 返回当前最大元素
        pq.pop();  // 移除当前最大元素
    }
    return 0;
}
```

最小堆示例：
```c++
#include <iostream>
#include <queue>
#include <vector>

int main() {
    std::priority_queue<int, std::vector<int>, std::greater<int>> pq;  // 最小堆

    pq.push(10);
    pq.push(30);
    pq.push(20);

    std::cout << "优先队列中的元素从小到大输出:\n";
    while (!pq.empty()) {
        std::cout << pq.top() << " ";  // 返回当前最小元素
        pq.pop();  // 移除当前最小元素
    }
    return 0;
}
```

C++中`std::priority_queue`是一个模板类，它的构造函数模板定义如下：

```c++
template<
	class T,						// 队列中储存的元素类型
	class Container = std::vector<T>,  // 底层容器类型（默认为std::vector）
	class Compare = std::less<typename Container::value_type>	//比较器（默认是std::less，也即最大堆）
>class priority_queue;
```

接下来我们分析构建最小堆优先队列的声明：`std::priority_queue<int, std::vector<int>, std::greater<int>> pq;`

`int`声明队列中存储的元素类型为`int`（整数），`std::vector<int>`使用`std::vector<int>`作为顶层容器，`std::greater<int>`使用`std::greater<int>`作为比较器，表示按照从小到大的顺序排序，实际上构建了一个小顶堆（堆顶为最小值）



## 哈希表

哈希表建立`key`与`value`之间的映射，实现高效的数据查询。且哈希表中进行增删查改的时间复杂度都是$O(1)$

在哈希表中，我们将每个数组中的每个空位称为桶(bucket)，每个桶可以储存一个键值对。而查询操作就是找到`key`对应的桶，并在桶中获取value

### 哈希函数

哈希函数的作用是将一个较大的输入空间映射到一个较小的输出空间。在哈希表中，输入空间是所有的`key`，输出空间则是所有的桶（数组索引）。也即我们可以通过哈希函数得到该key对应的键值对在数组中的存储位置

- 计算过程：
	输入一个`key`，哈希函数的计算过程分为以下两步：
	1. 通过某种哈希算法`hash()`计算得到哈希值
	2. 将哈希值对桶数量（数组长度）`capacity`取模，从而获取该`key`对应的数组索引`index`
	```c++
	index = hash(key) % capacity
	```
	

![图片alt](https://www.hello-algo.com/chapter_hashing/hash_map.assets/hash_function.png)

### 哈希冲突与扩容

**哈希冲突(hash collision)：** 之前我们提到，哈希函数的作用是将所有key构成的输入空间映射到数组所有索引构成的输出空间，而输入空间往往远远大于输出空间。因此，理论上一定存在“多个输入对应相同输出”的情况。比如我们提到的哈希函数`index = key % 100`在key=12836 20336的情况下就会得到相同的index。我们将这种多个输入对应同一输出的情况称为哈希冲突。

**负载因子(load factor)：** 哈希表的元素数量$\div$桶数量，用于衡量哈希冲突的严重程度，也常作为哈希表扩容的触发条件。

哈希冲突会导致查询结果错误，严重影响哈希表的可用性。容易想到的是，哈希表容量$n$越大，多个`key`被分配到同一个bucket的概率就越低，冲突就越少（因为哈希函数的计算过程就分为两步，第一步是计算得到哈希值，**第二步是哈希值对bucket的数量取模**，扩容了即将bucket的数量变多了）。因此我们可以通过扩容哈希表来减少冲突。

![图片alt](https://www.hello-algo.com/chapter_hashing/hash_map.assets/hash_table_reshash.png)

然而哈希表扩容像数组扩容那样，需要将所有键值对从原哈希表迁移至新哈希表，非常耗时；且由于哈希表容量`capacity`改变，我们需要通过哈希函数来重新计算所有键值对的存储位置，这进一步增加了扩容过程的计算开销。为此，编程语言通常会预留足够大的哈希表容量，防止频繁扩容。

哈希表扩容需要进行大量的数据搬运与哈希值计算，为了提升效率，我们可以采用以下策略：

1. 改良哈希表数据结构，使得哈希表可以在出现哈希冲突时正常工作
2. 仅在必要时，即当哈希冲突比较严重时，才进行扩容操作

哈希表的结构改良方法主要包括“链式地址”和“开放寻址”

#### 链式地址(separate chaining)
链式地址是将单个元素转化为链表（也即每个`bucket`中都存放链表），将键值对作为链表节点，将所有发生冲突的键值对都存储在同一链表中

![图片alt](https://www.hello-algo.com/chapter_hashing/hash_collision.assets/hash_table_chaining.png)

这种基于链式地址实现的哈希表的操作方法如下：

- **查询元素：** 输入`key`，经过哈希函数得到`bucket`的索引，即可访问链表的头节点，然后遍历链表并对比`key`以查找目标键值对
- **添加元素：** 首先通过哈希函数访问链表头节点，然后将节点（键值对）添加到链表中
- **删除元素：** 根据哈希函数的结果访问链表头部，接着遍历链表以查找目标节点并将其删除

但是链式地址也存在着以下局限性：
- **占用空间增大：** 链表包含节点指针，相比数组更加耗费内存空间
- **查询效率降低：** 需要线性遍历链表来查找对应元素

当链表很场的时候，查询效率$O(n)$很差。此时我们可以将链表转化为“AVL树”或“红黑树”，从而将查询操作的时间复杂度优化至$O(\log n)$。

#### 开放寻址(open addressing)

开放寻址并不引入额外的数据结构，而是通过“多次探测”来处理哈希冲突（直接在哈希表内部寻找新的位置来存储冲突的元素），探测方式主要包括线性探测、平方探测（二次探测）和多次哈希等

1. **开放寻址的基本原理：**
	- **初始插入：** 当我们插入一个键值对`(key, value)`时，通过哈希函数`hashFunc(key)`计算哈希值`index`，然后尝试在`index`位置插入该键值对
	- **冲突处理（探查）：** 如果该位置已经有键值对（发生冲突），就按照预设的探查策略寻找下一个可用的位置。
	- **查询和删除：** 查询和删除操作使用与插入相同的探查方式来定位元素。

1. **线性探测**

线性探测采用固定步长的现行搜索来进行探测，操作方法如下：
	- **插入元素：** 通过哈希计算桶索引，若发现桶内已有元素，则从冲突位置向后线性遍历（步长通常为1，直至找到空桶，将元素插入其中
	- **查找元素：** 若发现哈希冲突，则使用相同步长向后进行线性遍历，知道找到对应元素，返回value计科；如果遇到空桶，说明目标元素不在哈希表中，返回None（c++中为nullptr）

![图片alt](https://www.hello-algo.com/chapter_hashing/hash_collision.assets/hash_table_linear_probing.png)

然而，线性探测容易产生**聚集现象**。在线性探测法中，发生冲突时我们会逐步检查相邻的下一个槽位（顺着“堆积”区域探测），直到找到一个空槽位，填充在这个密集区域的末尾，进一步扩大这个堆积，最终导致**增删查改操作效率劣化（这是聚集现象的后果）**。

并且尤其需要注意的是，**我们不能在开放寻址哈希表中直接删除元素**。因为删除元素会在数组内产生一个空桶`None`，而当查询元素时，线性探测到该空桶就会返回，因此在该空桶之下的元素都无法再被访问到，程序可能误判这些元素不存在

![图片alt](https://www.hello-algo.com/chapter_hashing/hash_collision.assets/hash_table_open_addressing_deletion.png)

为了解决上述问题，我们可以采用**懒删除(lazy deletion)**机制：它不直接从哈希表中移除元素，而是利用一个常量`TOMBSTONE`来标记这个bucket。在该机制下，`none`和`TOMBSTONE`都代表空桶，可以放置键值对，但不同的是，线性探测到`TOMBSTONE`后应当继续遍历

然而**懒删除也可能会加速哈希表的性能退化**，因为每次删除操作都会产生一个删除标记，随着`TOMBSTONE`
的增加，搜索时间也会增加，因为线性探测可能需要跳过多个`TOMBSTONE`才能找到目标元素

为此，我们可以考虑在线性探测中记录遇到的首个`TOMBSTONE`的索引，并将搜索到的目标元素与该`TOMBSTONE`交换位置。这样做的好处是当每次查询或添加元素时，元素会被移到距离理想位置（探测起始点）更近的桶，从而优化查询效率

2. **平方探测**

平方探测不是简单地跳过一个固定的步数，而是跳过“探测次数的平方”，即1,4,9……步

平方探测主要具有以下优势：
- 平方探测通过跳过探测次数平方的距离，试图缓解线性探测的聚集效应
- 平方探测会跳过更大的距离来寻找空位置，有助于数据分布得更加均匀

但是平方探测也有缺陷：
- 仍然存在聚集现象
- 由于平方的增长，平方探测可能不会探测整个哈希表，这意味着即使哈希表中有空桶，平方探测也可能无法访问到它

3. **多次哈希**

多次哈希方法即使用多个哈希函数$f_1(x)、f_2(x)、f_3(x)、……$进行探测

其操作方法如下：
	- **插入元素：** 若哈希函数$f_1(x)$出现冲突，则尝试$f_2(x)$，以此类推，直到找到空位后插入元素
	- **查找元素：** 在相同的哈希函数顺序下进行查找，直到找到目标元素时返回；若遇到空位或已尝试所有哈希函数，说明哈希表中不存在钙元素，则返回`None`

与线性探测相比，多次哈希方法不易产生聚集，但多个哈希函数会带来额外的计算量

>开放寻址（线性探测、平方探测和多次哈希）的哈希表都存在“不能直接删除元素”的问题
>

### 哈希算法

由前面两小节我们知道，无论是开放寻址还是链式地址，都只能保证哈希表可以在发生冲突时正常工作，却无法减少哈希冲突的发生。如果哈希冲突过于频繁，那么哈希表的性能就会急剧变差。对于链式地址的哈希表，理想情况下键值对均匀分布在各个桶中，达到最佳查询效率；最差情况下所有键值对都存储到同一个桶中，时间复杂度退化至$O(n)$

![图片alt](https://www.hello-algo.com/chapter_hashing/hash_algorithm.assets/hash_collision_best_worst_condition.png)

我们回忆一下哈希函数的计算步骤
`index = hash(key) % capacity`，而`capacity`固定时，`index`就由哈希算法`hash()`决定，所以为了降低哈希冲突发生的概率，我们的目光自然而然地落到了哈希算法`hash()`的设计上

#### 哈希算法的目标
- **确定性：** 意指对于相同的输入，哈希算法始终产生相同的输出
- **高效性：** 计算哈希值的过程快，计算开销小
- **均匀分布：** 哈希算法应当使得键值对能够均匀分布在哈希表中，因为分布越均匀，哈希冲突的概率就越低

>当然如果是密码学应用的话，哈希算法需要具备更高级的安全特性。如，单向性：无法通过哈希值反推出输入数据的任何信息；抗碰撞性：极难找到两个不同的输入，使得它们的哈希值相同；雪崩效应：输入的微小变化应当导致输出的显著且不可预测的变化

#### 哈希算法的简单设计：

1. **加法哈希：** 对输入的每个字符的ASCII码相加，将得到的总和作为哈希值
2. **乘法哈希：** 利用乘法的不相关性，每轮乘以一个常数，将各个字符的ASCII码累积到哈希值中
3. **异或哈希：** 将输入数据的每个元素通过疑惑操作积累到一个哈希值中
4. **旋转哈希：** 将每个字符的ASCII码累积到一个哈希值中，每次累积之前都会对哈希值进行旋转操作（这里的旋转是指将一个数值的二进制表示中的某些位向左或向右移动一定位置，同时将移出的位重新放置到另一端，形成一个新的数值。这种操作可以增加输出的随机性和分布的均匀性）






## 二叉树（binary tree）

### 认识二叉树

二叉树是一种非线性数据结构，其基本单元是节点，每个节点包含值、左子结点引用和右子节点的引用

```c++
//二叉树节点结构体
struct TreeNode{
	int value;       // 节点值
	TreeNode *left;  // 左子结点指针
	TreeNode *right; // 右子节点指针
	TreeNode(int x){ // 构造函数
		value = x;
		left = nullptr;
		right = nullptr;
	}
}
```

#### 二叉树常见术语
- **根节点（root node）**：位于二叉树顶层的节点，没有父节点
- **叶节点（leaf node）**：没有子节点的节点，其两个指针均指向`nullptr`
- **边（edge）**：连接两个节点的线段，即节点引用（指针）
- 节点所在的**层（level）**：从顶至底递增，根节点所在层位 1
- 节点的**度（degree）**：节点的子节点的数量。在二叉树中，度的取值范围是0、1、2
- 二叉树的**高度（height）**：从根节点到最远节点所经过的边的数量
- 节点的**深度（depth）**：从根节点到该节点所经过的边的数量
- 节点的**高度（height）**：从距离该节点最远的叶节点到该节点所经过的边的数量

#### 二叉树的基本操作
1. 初始化二叉树

```c++
TreeNode* n1 = new TreeNode(1);
TreeNode* n2 = new TreeNode(2);
TreeNode* n3 = new TreeNode(3);
TreeNode* n4 = new TreeNode(4);
TreeNode* n5 = new TreeNode(5);

n1->left = n2;
n1->right = n3;
n2->left = n4;
n2->right = n5;
```
![图片alt](https://www.hello-algo.com/chapter_tree/binary_tree.assets/binary_tree_add_remove.png)
2. 插入或删除节点
由于插入节点可能会改变二叉树原有的逻辑结构，而删除节点通常意味着删除该节点及其所有子树，因此，在二叉树中，插入与删除通常由一套操作配合完成。
```c++
//这里我们在n1和n2节点中插入一个P节点
TreeNode* P = new TreeNode(0);

//插入P节点
n1->left = p;
p->left = n2;

//删除P节点
n1 -> left = n2;
delete p;
```

#### 常见二叉树类型

1. 完美二叉树（perfect binary tree）

所有层的节点都被完全填满（所有的叶节点需要在同一层上）。在完美二叉树（也叫满二叉树）中，叶节点的度为0，其余所有节点的度都为2；若树的高度为h，则节点总数为$2^\text{h+1}-1$其实就是等比数列求和
$$
  1+2^1+2^2+……+2^h=\frac{1*(1-2^\text{h+1})}{\text{1-2}}=2^\text{h+1}-1
$$
![图片alt](https://www.hello-algo.com/chapter_tree/binary_tree.assets/perfect_binary_tree.png)

2. 完全二叉树（complete binary tree）

只有最底层的节点未被填满,且最底层节点**尽量靠左填充**(注意这里指的是在最后一层,所有的节点都**连续排列在最左边的位置**而没有空缺,这个***尽量***可不是那种"尽力了,尽力了")

![图片alt](https://www.hello-algo.com/chapter_tree/binary_tree.assets/complete_binary_tree.png)

3. 完满二叉树(full binary tree)

除了叶节点之外，其余节点都有两个子节点（和**完美二叉树**的区别在于不要求所有叶节点在同一层上）

![图片alt](https://www.hello-algo.com/chapter_tree/binary_tree.assets/full_binary_tree.png)

4. 平衡二叉树(balanced binary tree)

任意节点的***左子树***和***右子树***的高度之差的绝对值不超过1

![图片alt](https://www.hello-algo.com/chapter_tree/binary_tree.assets/balanced_binary_tree.png)

#### 二叉树的退化

- 二叉树的理想结构是二叉树的每层节点都被填满，达到“完美二叉树”
- 而当所有节点都偏向一侧时，这是二叉树达到了另一个极端，退化为链表，各项操作都变为线性操作，时间复杂度退化至$O(n)$

### 二叉树的遍历

#### 层序遍历（level-order traversal）
层序遍历本质上属于广度优先遍历(breadth-first traversal)，也称为广度优先搜索(breadth-first search,BFS)，这是图论和数据结构中常用的一种遍历和搜索算法。它们的主要特点是按照层次顺序访问节点，先访问离起始节点较近的节点，再逐渐向外扩展。

从顶部逐层遍历二叉树，并在每一层按照从左到右的顺序访问节点

![图片alt](https://www.hello-algo.com/chapter_tree/binary_tree_traversal.assets/binary_tree_bfs.png)

>其实下面这串代码是这样的，我们从根节点开始遍历，依次将每一层的节点按从左到右的顺序遍历加入向量中。首先我们将根节点入队，然后每次从队首取出一个节点，并将其value加入vec中，然后我们再将其子节点入队，注意这并不影响同级节点，同级节点在队列中仍然排在其子节点的前面。这样，在队列不为空的情况下，我们不断重复这个过程，就实现了二叉树的层序遍历。

```c++
vector<int> levelOrder(TreeNode* root){
	queue<TreeNode* > queue;
	queue.push(root);
	
	vector<int> vec;
	while(!queue.empty()){
		TreeNode* node = queue.front()
		queue.pop()
		vec.push_back(node->value);
		if(node->left != nullptr){
			queue.push(node->left);
		}
		if(node->right != nullptr){
			queue.push(node->right);
		}
	}
	return vec;
}
```

#### 前序、中序、后序遍历

前序、中序、后序遍历都属于深度优先遍历(depth-first traversal)，也称为深度优先搜索(depth-first search)

深度优先遍历（Depth-First Traversal, DFT）和深度优先搜索（Depth-First Search, DFS）是图论和树结构中常用的遍历和搜索算法。它们的主要特点是沿着树的深度方向遍历节点，尽可能深地搜索树的分支，直到无法继续深入，然后回溯到上一个节点，继续探索其他分支。

![图片alt](https://www.hello-algo.com/chapter_tree/binary_tree_traversal.assets/binary_tree_dfs.png)

常见的深度优先遍历方法有三种，通常基于递归实现：

1. **前序遍历（Preorder Traversal）**：访问根节点 -> 递归访问左子树 -> 递归访问右子树。
2. **中序遍历（Inorder Traversal）**：递归访问左子树 -> 访问根节点 -> 递归访问右子树。
3. **后序遍历（Postorder Traversal）**：递归访问左子树 -> 递归访问右子树 -> 访问根节点。

假设有一棵二叉树如下：

```
        1
       / \
      2   3
     / \   \
    4   5   6
```

- **前序遍历**：1 -> 2 -> 4 -> 5 -> 3 -> 6
- **中序遍历**：4 -> 2 -> 5 -> 1 -> 3 -> 6
- **后序遍历**：4 -> 5 -> 2 -> 6 -> 3 -> 1

基于递归实现深度优先遍历：
```c++
//前序遍历
void preOrder(TreeNode *root){
	if(root == nullptr) // 注意这里的判断非常重要，这决定着递归终点，当递归到根节点时，就只执行了vec.push_back(root->val)
		return;
	//访问优先级：根节点 -> 左子树 -> 右子树
	vec.push_back(root->val);
	preOrder(root->left);
	preOrder(root->right);
}

//中序遍历
void inOrder(TreeNode *root){
	if(root == nullptr)
		return;
	//访问优先级：左子树 -> 根节点 -> 右子树
	inOrder(root->left);
	vec.push_back(root->val);
	inOrder(root->right);
}

//后序遍历
void postOrder(TreeNode *root){
	if (root == nullptr)
		return;
	//访问优先级：左子树 -> 右子树 -> 根节点
	postOrder(root->left);
	postOrder(root->right);
	vec.push_back(root->val);
}
```

>所以其实这里的xx序遍历其实指的是**访问根节点的顺序**，前序遍历最先访问根节点，中序遍历在中间访问根节点，后序遍历最后访问根节点
>

### 二叉搜索树

二叉搜索树满足以下条件：

1. 对于根节点，左子树中所有节点的值 < 根节点的值 < 右子树中所有节点的值
2. 任意节点的左、右子树也满足条件1

#### 二叉搜索树的操作

1. 查找节点

给定目标节点值`num`，我们可以根据二叉搜索树的性质来查找，从二叉树的根节点`root`出发，循环比较节点值`cur.val`和`num`之间的大小关系

- 若`cur.val < num`，说明目标节点在`cur`的右子树中，执行`cur = cur.right`
- 若`cur.val > num`，说明目标节点在`cur`的左子树中，执行`cur = cur.left`
- 若`cur.val = num`，说明找到目标节点，跳出循环并返回该节点

二叉搜索树的查找操作与二分查找算法的工作原理一致，都是每轮排除一般的情况，因此循环次数最多为二叉树的高度，当二叉树平衡时，时间复杂度为$O(log\ n)$

```c++
TreeNode* search(int num){
	TreeNode* cur = root;
	//循环查找，越过叶节点后跳出
	while(cur != nullptr ){
		//目标节点在cur的右子树中
		if(cur->val < num)
			cur = cur->right;
		//目标节点在cur的左子树中
		else if (cur->val > num)
			cur = cur->left;
		else
         //找到目标节点，跳出循环
			break;
	}
	//返回目标节点
	return cur;
}
```

2. 插入节点

插入给定的元素`num`，需要保持二叉搜索树“左子树<根节点<右子树”的性质，**时间复杂度也为$O(log\ n)$**

- **查找插入位置：** 跟查找操作类似，从根节点出发，根据当前节点值和`num`的大小关系循环向下搜索，直到越过叶节点（遍历至`nullptr`）时跳出循环
- **再改位置插入节点：** 初始化节点`num`，将该节点置于`nullptr`的位置

>但是需要注意两点：1. **二叉树不允许存在重复节点**，因此若待插入节点在树中已经存在，则不执行插入直接返回。 2. **借助节点`pre`保存上一轮循坏的节点**，这样在遍历至`nullptr`时我们可以获取其父节点，从而完成节点插入操作

```c++
void insert(int num){
	//若树为空，则初始化根节点
	if(root == nullptr){
		root = new TreeNode(num);
		return;
	}
	TreeNode *cur = root, *pre = nullptr;
	//循环查找，超过叶节点后跳出，因为查找是二分查找的
	while(cur != nullptr){
		//若树为空，则直接初始化根节点，将num作为根节点的值
		if(cur->val == num)
			return;
		pre = cur;
		if(cur->val < num){
			cur = cur->right;
		}
		else
			cur = cur->left;
	}
	TreeNode* newNode = new TreeNode(num);
	if(pre->val < num){
		pre->right = newNode;
	}
	else{
		pre->left = newNode;
	}
}
```

3. 删除节点

二叉搜索树的删除比二叉搜索树的插入更复杂一些，因为我们需要保证在删除操作完成后，二叉搜索树的“左子树<根节点<右子树”的性质仍然满足"，因此我们需要根据目标节点的子节点数量，分0、1、2三种情况，执行对应的删除节点操作

- 当待删除节点的度为0时，表示该节点是叶节点，可以直接删除

![图片alt](https://www.hello-algo.com/chapter_tree/binary_search_tree.assets/bst_remove_case1.png)

- 当被删除节点的度为1时，将待删除节点替换为其子节点即可

![图片alt](https://www.hello-algo.com/chapter_tree/binary_search_tree.assets/bst_remove_case2.png)

- **当待删除节点的度为2时，我们不能直接删除它，需要用一个节点来替换该节点。**并且因为要保持二叉搜索树“左子树<根节点<右子树”的性质，**这个节点可以是右子树的最小节点或左子树的最大节点**，这里说的左子树和右子树是指待删除节点下的左子树或右子树。
>当选择右子树的最小节点来替换待删除节点时，这个最小节点的值大于待删除节点左子树的所有节点值，且小于待删除节点右子树中除它自身外的所有节点值，替换后能够保证新的树结构仍然满足二叉搜索树的性质。同理，选择左子树的最大节点替换也能维持二叉搜索树的性质。

假设我们选择右子树的最小节点（中序遍历序列的下一个节点）

演示链接:https://www.hello-algo.com/chapter_tree/binary_search_tree/#__tabbed_4_1

**删除节点操作的时间复杂度为$O(log\ n)$，其中查找待删除节点需要$O(log\ n)$时间，获取中序遍历后继节点需要$O(log\ n)$时间**，示例代码（**这个还是挺难的**）如下：

```c++
void remove(int num){
	//若树为空，则直接返回
	if(root == nullptr)
		return;
	TreeNode *cur = root, *pre = nullptr;
	//循环查找，超过叶节点后跳出
	while(cur != nullptr){
		//找到待删除节点，跳出循环
		if(cur->val == num)
			break;
		pre = cur;
		if(cur->val < num){
			cur = cur->right;
		}
		else
            cur = cur->left;
    }
    if(cur = nullptr)
        return;
    //子节点数量为0或1
    if(cur->left == nullptr || cur->right == nullptr){
        TreeNode* child;
        if(cur->left != nullptr){
            child = cur->left;
        }else{
            child = cur->right;
        }
        //删除节点cur
        if(cur != root){
            if(pre->left == cur)
                pre->left = child;
            else
                pre->right = child;
        }else{
            //若删除节点为根节点，则重新指定根节点
            root = child;
        }
        delete cur;
    }
    //子节点数量为2，这里还不是很明白
    else{
        // 这里是为了寻找右子树中的最小节点
        TreeNode* tmp = cur->right;
        while(tmp->left != nullptr){
            tmp = tmp->left;
        }
        // 找到了右子树中的最小节点，以tmpVal记其的值
        int tmpVal = tmp->val;
        //递 归删除节点tmp（这里是因为我们用了右子树中的最小节点来替代我们要删除的根节点，所以我们右子树中的最小节点其实已经被挪走了，所以我们也要把tmp给删除）
        remove(tmp->val);
        cur->val = tmpVal;
    }
}
```

4. 中序遍历有序

二叉树的中序遍历遵循“左->根->右”的遍历顺序，而二叉搜索树又满足“左子结点<根节点<右子节点”的大小关系。也就是说，在二叉搜索树中进行中序遍历时，总是会优先遍历下一个最小节点，从而得出一个重要性质：**二叉搜索树的中序遍历是升序的**。因此，**我们在二叉搜索树中获取有序数据的时间复杂度是$O(n)$**，也即遍历即可，而无需进行额外的排序操作。



二叉搜索树的时间复杂度：

插入节点的时间复杂度为$O(log\ n)$，删除节点的时间复杂度为$O(log\ n)$，获取有序数据的时间复杂度为$O(n)$

### AVL树

我们知道，在多次插入和删除操作后，二叉搜索树有可能退化为链表，这种情况下，所有操作的时间复杂度都将从$O(log\ n)$劣化为$O(n)$

删除节点操作导致退化：
![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_degradation_from_removing_node.png)

插入节点操作导致退化：
![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_degradation_from_inserting_node.png)

而AVL树既是二叉搜索树，也是平衡二叉树，同时满足这两类树的所有性质，因此是一种平衡二叉搜索树(balanced binary search tree)。**注意AVL树为了保持平衡，引入了height这个成员变量，所以我们在做完给类操作之后也要注意对这个变量进行维护**

```c++
struct TreeNode{
	int val;
	int height;
	TreeNode* left;
	TreeNode* right;
	//默认构造函数，当不传递任何参数时调用此构造函数
	TreeNode(){
		val = 0;
		height = 0;
		left = nullptr;
		right = nullptr;
	} 
	//带参数构造函数，需要初始化一个特定值时调用此构造函数
	explicit TreeNode(int x){//explicit用于修饰构造函数或转换运算符，其作用是防止隐式类型转换，避免意外错误
		val = x;
		height = 0;
		left = nullptr;
		right = nullptr;
	}
}
```

#### AVL树常见术语

1. 节点高度
节点高度是指从该节点到它的最远叶节点的距离，也即经过的“边”的数量。需要特别注意的是，叶节点的高度为0，而空节点的高度为$-1$，我们可以创建两个函数用于获取和更新节点的高度

```c++
int height(TreeNode* node){
	if(node == nullptr){
		return -1;
	}else{
		return node->height; 
	}
}

void updateheight(TreeNode* node){
	if(node != nullptr){
		int leftHeight = height(node->left);
		int rightHeight = height(node->right);
		node->height = (leftHeight > rightHeight ? leftHeight : rightHeight) + 1;
	}
}
```

2. 节点平衡因子
即节点左子树高度减去节点右子树的高度，并且规定空节点的平衡因子为0
设平衡因子为$f$，则AVL树的任意节点的平衡因子均满足$-1\leq f\leq1$

```c++
int balanceFactor(TreeNode* node){
	if(node == nullptr){
		return 0;
	}
	return height(node->left) - height(node->right);
}
```

#### AVL树的旋转

AVL树的旋转操作能够在不影响二叉树的**中序遍历序列**（因为中序遍历能够保持有序，所以可能二叉搜索树用的比较多的都是中序遍历）的前提下，使失衡节点（指平衡因子的绝对值>1的节点）重新恢复平衡，也就是说，**旋转操作既能保持“二叉搜索树”的性质，也能使树重新变为“平衡二叉树”**

根据节点失衡情况的不同，旋转操作可以分为四种：右旋、左旋、先右旋后左旋、先左旋后右旋，下面详细介绍这些操作

1. 右旋
从底至顶看，二叉树中首个失衡节点是节点“3”，我们关注以该失衡节点为根节点的子树，将该节点记为`node`，其左子结点记为`child`,执行“右旋”操作。完成右旋后，子树恢复平衡，并且仍然保持二叉搜索树的性质。

![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_right_rotate_step1.png)

![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_right_rotate_step3.png)

当节点`child`有右子节点（记为`grand_child`）时，需要在右旋中添加一步，即将`grand_child`作为`node`的左子结点

![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_right_rotate_with_grandchild.png)

以这个图为例，我们可以看到，从底向顶看，这时3不再是失衡节点（左子树高度为2，右子树高度为1，平衡因子为1），而5是第一个失衡节点，其左子结点`child`有右子节点`grand_child`

右旋的代码示例如下：

```c++
TreeNode* rightRotate(TreeNode* node){
	TreeNode* child = node->left;
	TreeNode* grandChild = child->right;
	child->right = node;
	node->left = grandChild;
	updateHeight(node);
	updateHeight(child);
	//返回旋转后子树的根节点
	return child;
	//注意这个在没有grand_child时也是正确的，因为此时child->right是nullptr，grandchild相应地也是nullptr
}
```

2. 左旋

左旋所做的操作和右旋是几乎镜像的

![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_left_rotate.png)

同理，当节点child有左子结点(记为grand_child)时，需要在左旋中添加一步：将grand_child作为node的左子结点

![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_left_rotate_with_grandchild.png)

其实，左旋和右旋操作在逻辑上是镜像对称的，它们分别解决的两种失衡情况也是对称的，基于对称性，我们只需要将右旋的实现代码中的所有`left`替换为`right`，所有的`right`替换为`left`，即可得到左旋的实现代码：
```c++
TreeNode* leftRotate(TreeNode* node){
	TreeNode* child = node->right;
	TreeNode* grandChild = child->left;
	child->left = node;
	node->right = grandChild;
	updateHeight(node);
	updateHeight(child);
	//返回旋转后子树的根节点
	return child;
}
```

3. 先左旋后右旋

我们知道，当失衡节点`node`在`child`右上方时我们采取的是右旋，左上方时采取的是左旋，但下图的情况中，我们仅用左旋或者右旋都无法使子树恢复平衡，此时需要先对child执行左旋，再对node执行右旋（从底至顶看）

![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_left_right_rotate.png)

而它的代码也比较简单，我们已有`leftRotate`函数和`rightRotate`函数，且先左旋后右旋操作我们将其分为了对child进行左旋和对node执行右旋两步操作。

```c++
// 注意要搞清楚我们在做单次右旋和单次左旋时函数的形参是谁？并不是child节点而是失衡节点node
TreeNode* leftThenRightRotate(TreeNode* node){
	//先对node的左子结点进行左旋
	node->left = leftRotate(node->left);
	//再对node进行右旋
	return rightRotate(node);
}
```

4. 先右旋后左旋

![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_right_left_rotate.png)

需要先对`child`执行“右旋”，再对`node`执行“左旋”

```c++
TreeNode* rightThenLeftRotate(TreeNode* node){
	node->right = rightRotate(node->right);
	return leftRotate(node);
}
```

5. 旋转的选择

可以这么记，**从底至顶向上看，如果失衡节点相对于其子节点的位置均为左或右，则对失衡节点施以左旋或右旋操作。**

我们以先左旋后右旋为例，从图中可以看出，节点1相对于节点2在左侧，故先左旋，而节点3相对于节点1在右侧，故后右旋。

![图片alt](https://www.hello-algo.com/chapter_tree/avl_tree.assets/avltree_rotation_cases.png)

而借助平衡因子，我们还有另一种判断旋转的方法，即**通过失衡节点的平衡因子以及较高一侧子节点的平衡因子的正负号**来确定应当采用哪种旋转方式，如下表所列：

| 失衡节点的平衡因子 | 子节点的平衡因子 | 应采用的旋转方法 |
|------------------|----------------|---------------|
| > 1 (左偏树)     | ≥ 0            | 右旋          |
| > 1 (左偏树)     | < 0            | 先左旋后右旋   |
| < -1 (右偏树)    | ≤ 0            | 左旋          |
| < -1 (右偏树)    | > 0            | 先右旋后左旋   |

为了便于使用，我们可以将旋转操作封装成一个函数，**对各种失衡情况进行旋转**，使失衡节点重新恢复平衡（用平衡因子来判断左偏右偏可以让我们很好地封装函数）

```c++
TreeNode* rotate(TreeNode* node){
	//获取节点node的平衡因子
	int _balanceFactor = balanceFactor(node);
	//左偏树
	if(_balanceFactor > 1){
		if(balanceFactor(node->left) >= 0){
			//右旋
			return rightRotate(node);
		}else{
			//先左旋后右旋
			node->left = leftRotate(node->left);
			return leftRotate(node);
		}
	}
	//右偏树
	if(_balanceFactor < -1){
		if(balanceFactor(node->right) <= 0){
			//左旋
			return leftRotate(node);
		}else{
			//先右旋后左旋
			node->right = rightRotate(node->right);
			return leftRotate(node);
		}
	}
	//平衡树，无需旋转，直接返回
	return node;
}
```

#### AVL树常用操作

1. 插入节点

AVL树的节点插入操作与二叉搜索树大体上类似，区别在于，在AVL树中插入节点后，从该节点到根节点的路径上可能会出现一系列失衡节点。因此，我们需要从这个节点开始，从底向上执行旋转操作，使所有失衡节点恢复平衡

```c++
void insert(int val){
	root = insertHelper(root, val);
}

TreeNode* insertHelper(TreeNode* node, int val){
	if(node == nullptr)
		return new TreeNode(val);
	if(val < node->val) // 即node节点是在插入节点的右边的，所以node->left指的就是插入节点
    	node->left = insertHelper(node->left, val);  // 如果val小于当前节点的值，即node->val，我们就递归地在左子树中寻找合适的位置插入，因此我们将val传递给insertHelper(node->left,val)，并将结果赋给node->left
    else if(val > node->val)
    	node->right = insertHelper(node->right, val);
    else 
    	return node;// 如果val等于当前节点的值，我们不插入重复的值，而是直接返回当前节点
    updateHeight(node);
    node = rotate(node);
    return node;
}
//这个插入操作是通过递归完成的，当递归到某个字数的根节点node为nullptr时，创建一个新节点并返回，然后从叶节点一路返回到根节点，逐层更新树的结构
```

AVL树的插入操作时间复杂度分析：
分为三个部分，**查找插入位置**、**更新高度信息**、**执行必要的旋转操作**
对于**查找插入位置**，显然时间复杂度为$O(log\ n)$；对于**更新高度信息**，插入新节点后，我们需要沿着从插入点到根节点的路径更新每个节点的高度，因为这条路径上的节点数量不会超过树的高度，所以最坏情况下，更新所有受影响节点的高度所需的时间复杂度也为$O(log\ n)$；对于执行必要的旋转操作：旋转本身是一个常数时间复杂度的操作，但是我们可能需要从插入点到根节点的路径上多次检查并执行旋转，时间复杂度也为$O(log\ n)$
故我们可以得出结论，AVL树的插入操作的总时间复杂度为$O(log\ n)$



2. 删除节点
和插入节点类似，AVL树的节点删除操作与二叉搜索树大体上也类似，区别在于需要在二叉搜索树的删除节点方法的基础上，从底至顶执行旋转操作，使得所有节点恢复平衡

```c++
/* 删除节点 */
void remove(int val) {
    root = removeHelper(root, val);
}

/* 递归删除节点（辅助方法） */
TreeNode *removeHelper(TreeNode *node, int val) {
    if (node == nullptr)
        return nullptr;
    /* 1. 查找节点并删除 */
    if (val < node->val)
        node->left = removeHelper(node->left, val);
    else if (val > node->val)
        node->right = removeHelper(node->right, val);
    else {
        if (node->left == nullptr || node->right == nullptr) {
            TreeNode *child = node->left != nullptr ? node->left : node->right;
            // 子节点数量 = 0 ，直接删除 node 并返回
            if (child == nullptr) {
                delete node;
                return nullptr;
            }
            // 子节点数量 = 1 ，直接删除 node
            else {
                delete node;
                node = child;
            }
        } else {
            // 子节点数量 = 2 ，则将中序遍历的下个节点删除，并用该节点替换当前节点
            TreeNode *temp = node->right;
            while (temp->left != nullptr) {
                temp = temp->left;
            }
            int tempVal = temp->val;
            node->right = removeHelper(node->right, temp->val);
            node->val = tempVal;
        }
    }
    updateHeight(node); // 更新节点高度
    /* 2. 执行旋转操作，使该子树重新恢复平衡 */
    node = rotate(node);
    // 返回子树的根节点
    return node;
}
```

AVL树删除节点的时间复杂度分析，分为四个部分，**查找要删除的节点、执行删除逻辑、更新高度信息、执行必要的旋转操作**

**查找要删除的节点：**这一步骤类似于二叉搜索树(BST)中的查找操作，时间复杂度显然为$O(log\ n)$
**执行删除逻辑：**也和二叉搜索树类似，时间复杂度也为$O(log\ n)$
**更新高度信息：**每当修改了树结构（包括删除节点和后续的旋转），都要回溯并更新受影响节点的高度，这条路径上的节点数量不会超过树的高度，更新高度的时间复杂度也为$O(log\ n)$
**执行必要的旋转操作：**一旦检测到失衡，就需要执行旋转来恢复平衡，每个旋转操作本身的时间复杂度为$O(1)$，但是最坏情况下，我们可能需要多次检查并执行旋转，时间复杂度仍为$O(log\ n)$
故**总的时间复杂度为$O(log\ n)$**

## 堆（heap）

### 堆概述

堆是一种满足特定条件的完全二叉树（本节我们默认是最为常用的二叉堆），主要可分为两种类型：
- 小顶堆(min heap)【最小堆】：任意节点的值$\leq$其子节点的值
- 大顶堆(max heap)【最大堆】：任意节点的值$\geq$其子节点的值

![图片alt](https://www.hello-algo.com/chapter_heap/heap.assets/min_heap_and_max_heap.png)

堆作为完全二叉树的一个特例，有以下特性：

1. 最底层节点靠左填充，其它层的节点都被填满
2. 二叉树的根节点称为“堆顶”，底层最靠右的节点称为“堆底”
3. 对于大顶堆（小顶堆），堆顶元素的值是最大（最小）的

#### 堆的常用操作

先介绍下优先队列(priority queue)，优先队列是一种特殊的队列数据结构，其中每个元素都附带一个**优先级**，并且元素按照优先级的顺序进行处理，而非按照进入队列的时间顺序（普通队列）。优先队列通常用于需要动态排序的场景，例如任务调度、路径规划（如Dijkstra算法）等

堆通常用于实现优先队列，**大顶堆相当于元素按从大到小的顺序出队的优先队列**，从使用角度来看，可以将“优先队列”和“堆”看做等价的数据结构。

在实际应用中，我们可以直接使用编程语言提供的堆类（或优先队列类），而C++的`std::priority_queue`就提供了这样的优先队列

#### 堆的实现（以大顶堆为例）

1. 堆的存储与表示

“二叉树的数组表示”一节中提到，完全二叉树非常适合用数组来表示，因为完全二叉树的前几层都有两个叶节点，而未排满的区域都只出现在最底层且靠右的位置，所以空位一定会出现在层序遍历序列的末尾，映射公式：**若某节点的索引为$i$，则该节点的左子节点索引为$2i+1$，右子节点索引为$2i+2$（根节点索引为0的情形）**就能很好地适用。

而我们知道，堆正是一种完全二叉树，因此我们可以使用数组来存储堆。

如图所示，给定某节点的索引$i$，则其左子节点的索引为$2i+1$，其右子节点的索引为$2i+2$，其父节点的索引为$\lfloor \frac{i-1}{2} \rfloor$。当索引越界时，表示空节点或节点不存在。

![图片alt](https://www.hello-algo.com/chapter_heap/heap.assets/representation_of_heap.png)

可以将索引映射公式封装成函数：

```c++
int left(int i){
	return 2*i+1;
}

int right(int i){
	return 2*i+2;
}

int parent(int i){
	return (i-1)/2;
}
```

2. 访问堆顶元素

```c++
int peek(){
	return maxHeap[0];
}
```

3. 元素入堆

给定元素`value`，我们将其添加至堆底，但是可能违反堆中元素的大小排序，致使堆的成立条件被破坏，因此我们需要修复从插入节点到根节点路径上的各个节点，这个操作称为堆化**(heapify)**

我们考虑从入堆节点开始从底至顶执行堆化，其大致流程如下：

比较插入节点与其父节点的值，如果插入节点更大，则将它们交换。然后继续执行此操作，从底至顶修复堆中的各个节点，**直至越过根节点或遇到无须交换的节点时结束**，即可修复该堆的性质。

动画演示链接：https://www.hello-algo.com/chapter_heap/heap/#2

**时间复杂度分析：**设节点总数为$n$，则树高为$O(log\ n)$。由此可知，堆化操作的循环次数最多为$O(log\ n)$，也即元素入堆操作的时间复杂度为$O(log\ n)$

> 我们在添加节点的时候是直接将其加入到堆底（也就是数组的末尾），这个操作的时间复杂度为$O(1)$，而堆化操作的时间复杂度为$O(log\ n)$

代码示例如下：

```c++
void push(int val){
	maxHeap.push_back(val);
	siftUp(maxHeap.size()-1);//这里maxHeap.size()返回的是当前堆中元素的个数，由于索引从0开始，且val我们添加至堆底，maxHeap.size()-1其实也就是val的索引（数组中最后一个元素的索引）
}

void siftUp(int i){
	while(true){
		int p = parent(i); //获取节点 i 的父节点
		if(p < 0 || maxHeap[i] <= maxHeap[p]) // 越过根节点或节点无须修复
			break;
		// 交换两节点
		swap(maxHeap[i], maxHeap[p]);
		// 循环向上堆化
		i = p;
	}
}
```

4. 堆顶元素出堆

堆顶元素是二叉树的根节点，即列表首元素。

我们**并不能直接从列表中删除首元素**，因为二叉树中所有节点的索引都会发生变化，这将使得后续使用堆化进行修复变得困难。为了尽量减少元素索引的变动，我们可以采取以下步骤：

- 交换堆顶元素与堆底元素（交换根节点与最右叶节点）
- 将堆底从列表中删除（这时堆底其实是原来的堆顶元素）
- 从根节点开始，**从顶至底**进行堆化

从顶至底进行堆化的逻辑如下：其操作方向与“从底至顶堆化”相反，我们**将根节点的值与其两个子节点的值进行比较，并将最大的子节点与根节点进行交换**。然后循环执行此操作，直到越过叶节点或遇到无须交换的节点时结束。

演示链接：[8.1  堆 - Hello 算法](https://www.hello-algo.com/chapter_heap/heap/#4)

**时间复杂度分析：**与元素入堆操作类似，栈顶元素出堆操作的时间复杂度也为$O(log\ n)$

示例代码如下：
```c++
void pop(){
	if(isEmpty()){
		throw out_of_range("堆为空")
	}
	swap(maxHeap[0],maxHeap[maxHeap.size()-1]);
	maxHeap.pop_back();
	siftDown(0);
}
// 从节点i开始，从顶至底堆化
void siftDown(int i){
	while(true){
		// 判断节点i,l,r中值最大的节点，其索引记为max
		int l = left(i), r = right(i), max = i; //前面已经将left()和right()封装成函数了，其实就是2*i+1和2*i+2
		if(l < maxHeap.size() && maxHeap[l] > maxHeap[max]){// 1.不越过叶节点；2.左子结点更大
			max = l;
		}
		if(r < maxHeap.size() && maxHeap[r] > maxHeap[max]){ //这里直接和maxHeap[max]对比，包括了和maxHeap[i]、maxHeap[l]对比
			max = r；
		}
		if(max == i){// 要注意判断一下是否需要交换，如果不需要交换就直接跳出循环
			break; //节点i最大或索引l,r越界的情形，无须继续进行堆化，跳出循环
		}
		
		swap(maxHeap[i], maxHeap[max]);
		i = max; //循环向下继续堆化
	}
}
```

### 建堆操作

即使用一个列表的所有元素来构建一个堆

#### 借助入堆操作实现

首先创建一个空堆，然后遍历链表，依次对每个元素执行入堆操作。也即将元素添加至堆的尾部，再对该元素执行从底至顶的堆化操作。

每当一个元素入堆，堆的长度就加一。由于节点是从顶到底依次被添加进二叉树的，因此堆是“自上而下”构建的。

若元素数量为n，每个元素的入堆操作时间复杂度为$O(log\ n)$，因此该建堆方法的时间复杂度为$O(n*logn)$。这里的计算是这样的$O(log1+log2+...+logn)=O(log(n!))=O(n*logn)$

#### 通过遍历堆化实现

这是一种更为高效的建堆方法，分为两步：
1. 将列表所有元素原封不动地添加到堆中，此时堆的性质尚未满足
2. 倒序遍历堆（层序遍历的倒序）对每个**非叶节点**执行**“从顶至底”的堆化**（这里指的是将该节点作为子树的根节点进行从顶至底的堆化）

每当堆化一个节点之后，以该节点为根节点的子树就形成了一个合法的子堆。而由于是倒序遍历，因此堆是“自下而上”构建的。需要注意的是，叶节点没有子节点，它们天然就是合法的子堆，无需堆化，我们前面也强调对非叶结点进行堆化。

最后一个非叶结点其实就是最后一个节点的父节点，通过这一点我们能很好地找到最后一个非叶结点，从其开始进行倒序遍历。示例代码如下：

```c++
MaxHeap(vector<int> nums){// 这是类的一个构造函数
	maxHeap = nums;// maxHeap也是一个vector<int>的动态数组
	// 堆化除叶节点以外的其他所有节点
	for(int i = parent(maxHeap.size() - 1); i >= 0; i--){
		siftDown(i)
	}
}
```

### Top-k问题

给定一个长度为n的无序数组`nums`，请返回数组中最大的k个元素。

#### 方法一：遍历选择

即分别在每轮中提取第1、2、……、k大的元素，时间复杂度为$O(nk)$，也就是说当k与n比较接近时，时间复杂度趋向于$O(n^2)$，非常耗时，故此方法只适用于k$\ll$n的情形。当k=n时，我们可以得到完整的有序序列，此时即“选择排序”算法

#### 方法二：排序

我们可以先对数组`nums`进行排序，再返回最右边的k个元素，这样的时间复杂度为$O(nlogn)$。显然这个方法已经“超额”完成任务，我们只需要找到最大的k个元素即可，并不需要对其他元素进行排序

#### 方法三：堆

我们可以基于堆更加高效地解决Top-k问题，流程如下：
1. **初始化一个小顶堆，其堆顶元素最小**
2. 将数组的前k个元素依次入堆
3. 从第k+1个元素开始，若当前元素大于堆顶元素，则将堆顶元素出堆，并将当前元素入堆
4. 遍历完成后即得最大的k个元素

演示链接：https://www.hello-algo.com/chapter_heap/top_k.assets/top_k_heap_step1.png

我们可以回顾一下堆的性质，来明确一下这中间的过程是怎么进行的。首先小顶堆并不是严格从小到大排序的，其满足堆顶元素最小，父节点的值$\leq$子节点的值。有的同学可能会有疑惑，当我们使堆顶元素出堆的时候，当前元素入堆的时候，为什么能保证还满足堆的性质呢，或者说堆顶元素怎么保证仍然是最小的呢。比如[3, 5, 4, 10, 8, 6]，其对应的堆的树形结构为

	        3
	      /   \
	     5     4
	    / \   /
	   10  8 6

**在堆顶元素出堆之后，C++的`priority_queue`会自动进行堆化操作来重新维护堆的性质**，其大致流程如下:

- 删除堆顶的3，用堆的最后一个元素6替代堆顶，得到临时堆：

  ```
       6
     /   \
    5     4
   / \
  10  8
  ```

- 对堆执行自顶向底的堆化，变为：
     ```
          4
        /   \
      5     6
    / \
   10  8
   ```
   
- 入堆，插入新元素7到堆的末尾，得到临时堆：
  
   ```
          4
        /   \
       5     6
      / \   /
     10  8  7
   ```
   
- 对堆执行自底向上的堆化（由于7比6大，不需要进行调整）：
  
   ```
         4
       /   \
      5     6
     / \   /
    10  8  7
  ```

最后得到的堆是[4, 5, 6, 10, 8, 7]，仍然符合小顶堆的性质

代码示例:

```c++
// 小顶堆的类型为priority_queue<int, vector<int>, greater<int>>，这是一个类型；而topKHeap是函数的名称，这个函数接受两个参数，vector<int> &nums 和 int k，nums是输入的数组，k是要找出的最大元素的数量
priority_queue<int, vector<int>, greater<int>> topKHeap(vector<int> &nums, int k){
	priority_queue<int, vector<int>, greater<int>> heap;
	// 将数组的前k个元素入堆
	for(int i = 0; i < k; i++){
		heap.push(nums[i]); //heap.push操作的时间复杂度为O(log k)，因为每次插入操作都需要维护堆的性质，所以对于前k个元素，需要执行k次heap.push操作，其时间复杂度为O(k*logk)
	}
	//从第k+1个元素开始，保持堆的长度为k
	for(int i = k; i < nums.size(); i++){
		if(nums[i] > heap.top()){
			heap.pop();
			heap.push(nums[i]);// 对于剩余n-k个元素，heap.top操作的时间复杂度为O(1)，每次heap.pop和heap.push的时间复杂度为O(log k)，因为每次都需要调整堆来保持性质。所以这部分的时间复杂度为O((n-k)*logk)
		}
	}
	return heap;
}
```

**时间复杂度分析：**

总共执行了n轮的入堆和出堆操作（最开始的k个元素入堆也是，从k+1个元素开始判断是否需要堆顶元素出堆以及入堆当前元素），每次堆操作的时间复杂度为$O(logk)$。这是因为堆的最大长度为k，而在出堆入堆之后都需要进行堆化，堆化的时间复杂度就是$O(logk)$，所以总的时间复杂度为$O(n*logk)$，这个方法的效率很高，当k较小时，时间复杂度趋向于$O(n)$，当K较大时，时间复杂度不会超过$O(n*logn)$

此外，该方法适用于动态数据流的使用场景。在不断加入数据时，我们可以持续维护堆内的元素，从而实现最大的k个元素的动态更新

## 图

### 图概述

图(graph)是一种非线性数据结构，由顶点(vertex)和边(edge)组成，可以将图G抽象地表示为一组顶点（V）和一组边（E）的集合

如果将顶点看做节点，将边看作连接各个节点的引用（指针），我们就可以将图看作一种由链表拓展而来的数据结构。相较于**线性关系（链表）**和**分治关系（树）**，网络关系（图）的自由度更高，因而更为复杂

![图片alt](https://www.hello-algo.com/chapter_graph/graph.assets/linkedlist_tree_graph.png)

#### 图的常见类型和术语

这里在离散数学学过了，就列举一下术语，**无向图(undirected graph)**、**有向图(directed graph)**，**连通图(connected graph)**、**非连通图(disconnected graph)**，**有权图(weighted graph)**，**邻接(adjacency)**，**路径(path)**，**度(degree)**

#### 图的表示

常用表示方法包括邻接矩阵和邻接表，下面以无向图为例

1. **邻接矩阵**

设图的顶点数量为n，邻接矩阵(adjacency matrix)使用一个n*n大小的矩阵来表示图，每一行（列）代表一个顶点，元素代表边，用1或0来表示两个顶点间是否存在边，这在离散数学也学过

邻接矩阵具有以下特性：

- 在简单图（不存在顶点到其自身的边，同一条边不重复出现）中，顶点不能与自身相连，此时邻接矩阵主对角线元素没有意义
- 对于无向图，两个方向的边等价，无向图的邻接矩阵必然是对称阵
- 将邻接矩阵的元素从1和0替换为权重，即可表示有权图

在使用邻接矩阵表示图时，我们可以直接访问矩阵元素来获取边，因此增删查改的效率很高，时间复杂度为$O(1)$，然而矩阵的空间复杂度为$O(n^2)$，占用内存较多

2. **邻接表**

邻接表(adjacency list)使用n个链表来表示图，链表节点表示订单，第i个链表对应顶点i，其中存储了该顶点的所有邻接顶点（与该顶点相连的顶点）

邻接表仅存储实际存在的边，边的总数通常远小于$n^2$，因此它更加节省空间，但是在邻接表中需要通过遍历链表来查找边，因此时间效率并不如邻接矩阵

![图片alt](https://www.hello-algo.com/chapter_graph/graph.assets/adjacency_list.png)

观察此图，我们可以发现，邻接表的结构与哈希表中的“链式地址”非常相似，因此我们也可以采用类似的方法来优化效率，比如链表较长时，我们可以将链表转为AVL树或红黑树，从而将时间效率从$O(n)$优化至$O(logn)$；还可以将链表转换为哈希表，从而将时间复杂度将至$O(1)$

### 图的基础操作

图的基础操作可以分为对边的操作和对顶点的操作，在邻接矩阵和邻接表两种表示方法下实现方式有些不同

#### 基于邻接矩阵的实现

给定一个顶点数量为n的无向图，各种操作的实现方式如下：

1. **添加或删除边：** 直接在邻接矩阵中修改指定的边即可（即修改邻接矩阵对应位置的值），时间复杂度为$O(1)$，并且需要注意的是，无向图需要同时更新邻接矩阵两个位置的值
2. **添加顶点：** 在邻接矩阵的尾部添加一行一列，并全部填0（因为只是加顶点，没有加边），时间复杂度为$O(n)$
3. **删除顶点：** 在邻接矩阵中删除一行一列。当删除首行首列时达到最差情况，此时需要将$(n-1)^2$个元素向左上方移动，时间复杂度为$O(n^2)$。因为删除操作并非真正的删除，而是将这一行一列的值改为0，然后将其他元素移过来补位置。

![图片alt](https://www.hello-algo.com/chapter_graph/graph_operations.assets/adjacency_matrix_step5_remove_vertex.png)

4. **初始化：** 传入n个顶点，初始化长度为n的顶点列表`vertices`，时间复杂度为$O(n)$；初始化$n*n$大小的邻接矩阵`adjMat`，时间复杂度为$O(n^2)$

下面是一个基于邻接矩阵表示图的实现代码

```c++
class GraphAdjMat{
    	vector<int> vertices;  		// 顶点列表，元素代表“顶点值”，索引代表“顶点索引”，也就是说vertices其实记录的是图里每个节点的实际值
    	vector<vector<int>> adjMat; // 邻接矩阵，行列索引对应顶点索引，adjMat记录的是图的顶点之间的连接关系，也就是是否存在边
	
public:
    // 构造方法
    GraphAdjMat(const vector<int> &vertices, const vector<vector<int>> &edges){
        /*注意这里的edges和edge，edges是二维的vector向量，而edge是edges里面的一个元素，也就是一维vector向量，而由于edge表示的是边，所以edge这个一维向量里面就只有两个元素，即边的端点的索引*/
        // 添加顶点
        for(int val : verticces){
            addVertex(val);
        }  
        // 添加边
        for(const vector<int> &edge : edges){
            // 这里edge[0],edge[1]的值其实就是这条边的两个端点的索引，一定要记得edge是一条边
            addEdge(edge[0], edge[1]);
        }
    }
    
    int size() const{
        return vertices.size();
    }
      
    void addVertex(int val){
        int n = size();
        // 向顶点列表中添加新定点的值
        vertices.push_back(val);
        /* 在邻接矩阵中添加一行，这里用的是emplace_back的方法，首先调用vector<int>(n,0)创建一个大小为n的一维向量，所有元素的初始值为0。然后使用emplace_back将这个一维向量直接构造到adjMat的末尾*/
        /*emplace_back是std::vector的方法，用于在容器的末尾直接构造一个元素，它和push_back的区别是push_back会先构造一个临时对象，然后将其复制或移动到容器中，emplace_back则直接在容器末尾构造对象，避免了临时对象的创建和移动，效率更高*/
        adjMat.emplace_back(vector<int>(n,0));
        // 在邻接矩阵中添加一列，这里其实就是遍历每一行，在每一行后面都加0。因为我们必须意识到表示矩阵的方式其实是一个二维向量，我们需要加一列，就相当于在每一个一维向量后面加一个元素，而只加节点不加边，也即将矩阵元素值赋为0
        for(vector<int> &row : adjMat){
            row.push_back(0);
        }
    }
    
    // 删除顶点
	void removeVertex(int index){
        if(index >= size()){
            throw out_of_range("顶点不存在");
        }
        // 在顶点列表中删除索引为index的顶点
        vertices.erase(vertices.begin() + index);
        // 在邻接矩阵中删除索引为index的行
        adjMat.erase(adjMat.begin() + index);
        // 在邻接矩阵中删除索引为index的列
        for(vector<int> &row : adjMat){
            row.erase(row.begin() + index);
        }
    }
    
    // 添加边
    void addEdge(int i, int j){
        if(i < 0 || j < 0 || i >= size() || j>= size() || i == j){
            throw out_of_range("顶点不存在");
        }
        adjMat[i][j] = 1;
        adjMat[j][i] = 1;
    }
    
    
    //删除边
    // 参数i，j对应vertices元素的索引
    void removeEdge(int i, int j){
        if(i < 0 || j < 0 || i >= size() || j >= size() || i == j) // i==j 为了避免自环边的操作，因为自环边在无向图中很少被使用，并且在一些实际场景下并没有意义，比如城市交通图中自环边表示城市与自身连接，社交网络中表示自己和自己是好友
            throw out_of_range("顶点不存在");
        adjMat[i][j] = 0;
        adjMat[j][i] = 0;
    }
    
    // 在原来的代码中似乎没有定义printVectorMatrix和printVector两个函数，下面补充其定义
    void printVector(const vector<int>& vec) {
    	cout << "[";
    	for (size_t i = 0; i < vec.size(); i++) {
        	cout << vec[i];
        	if (i != vec.size() - 1) cout << ", "; // 如果不是最后一个元素，添加逗号分隔符
    	}
    	cout << "]" << endl;
	}
    
    void printVectorMatrix(const vector<vector<int>>& mat) {
    	for (const auto& row : mat) {
        	for (size_t i = 0; i < row.size(); i++) {
            	cout << row[i];
            	if (i != row.size() - 1) cout << " "; // 如果不是最后一个元素，添加空格分隔符
        	}
        	cout << endl; // 换行表示下一行
    	}
	}


    
    void print(){
        cout << "顶点列表 = ";
        printVector(vertices);
        cout << "邻接矩阵 = " << endl;
        printVectorMatirx(adjMat);
    }
    
}
```

#### 基于邻接表的实现

设无向图的总定点数为n，总边数为m，则可以实现以下操作：

演示链接(https://www.hello-algo.com/chapter_graph/graph_operations.assets/adjacency_list_step2_add_edge.png)

- **添加边：** 在顶点对应链表的末尾添加边即可，时间复杂度为$O(1)$（直接添加到顶点列表的顶点之后的位置，不需要遍历直到链表的末尾），且因为是无向图，需要同时添加两个方向的边

- **删除顶点：** 需遍历整个邻接表，删除包含指定顶点的所有边，时间复杂度为$O(n+m)$

   - 适用于密集图

   缺点：

   - 空间浪费（尤其是对于稀疏图），其空间复杂度为$O(n^2)$
   - 添加、删除顶点的操作复杂，添加顶点的时间复杂度为$O(n)$，删除顶点的时间复杂度为$O(n^2)$

2. **邻接表**

   优点：

   - 空间效率高，相比于邻接矩阵节省了大量空间，邻接表的空间复杂度为$O(n+m)$，其中$n$是顶点数，$m$是边数。与邻接矩阵相比，邻接表只储存实际存在的边，因此更节省空间
   - 动态修改方便，比如

   缺点：

   - 查找边是否存在的效率低，需要遍历邻接表
   - 实现复杂，需要处理链表或者动态数组

### 图的遍历

树代表的是“一对多”的关系，而图显然具有更高的自由度，可以表示任意的“多对多”关系。因此，我们可以把树看作图的一种特例。显然，树的遍历操作也是图的遍历操作的一种特例。

图和树都需要应用搜索算法来实现遍历操作，图的遍历方式也可以分为两种：广度优先遍历和深度优先遍历

#### 广度优先遍历

广度优先遍历是一种由近及远的遍历方式，从某个节点出发，始终有限访问距离最近的顶点，并一层层向外扩张。如下图所示：

![图片alt](https://www.hello-algo.com/chapter_graph/graph_traversal.assets/graph_bfs.png)

从左上角顶点出发，首先遍历该顶点的所有邻接顶点，然后遍历下一个顶点的所有邻接顶点，以此类推，直至所有节点访问完毕。

**算法实现**

BFS通常借助队列来实现，队列具有“先入先出”的性质，这与BFS的“由近及远”的思想异曲同工，其大致流程如下：

1. 将遍历起始顶点`startVet`加入队列，然后开启循环
2. 在循环的每轮迭代中，弹出队首顶点并记录访问，然后将该顶点的所有邻接顶点加入到队列尾部
3. 循环步骤2，纸质所有顶点被访问完毕后结束

```c++
//使用邻接表来表示图，以便获取指定顶点的所有邻接顶点
// vertex是顶点，这个graphBFS函数的返回类型是包含指向vertex的指针的一个vector向量
vector<Vertex *> graphBFS(GraphAdjList &graph, Vertex *startVet){
    // 顶点遍历序列
    vector<Vertex *> res;
    //哈希集合，用于记录已经被访问过的顶点
    unordered_set<Vertex *> visited = {startVet};
    // 队列，用于实现BFS
    queue<Vertex*> que;
    que.push(startVet);
    while(!que.empty()){
        Vertex *vet = que.front();
        que.pop();
        res.pushback(vet); // 记录访问顶点
        for(auto adjVet : graph.adjList[Vet]){
            if(visited.count(adjVet))
                continue;	// 跳过已被访问的顶点
            que.push(adjVet);
            visited.emplace(adjVet);
        }
    }
     return res;
}
```

**复杂度分析**

- **时间复杂度：**所有顶点都会入队，出队一次，使用$O(V)$时间；在遍历邻接顶点的过程中，由于是无向图，所有边都会被访问2次，使用$O(E)$时间，总体使用$O(V+E)$时间
- **空间复杂度：** 列表`res`，哈希集合`visited`，队列`que`中的顶点数量最多为$|V|$，使用$O(|V|)$空间

#### 深度优先遍历

**深度优先遍历是一种优先走到底，无路可走再回头的遍历方式**。如下图所示，从左上角顶点出发，访问当前顶点的某个邻接顶点，直到走到尽头时返回，再继续走到尽头并返回，以此类推，直至所有顶点遍历完成

![图片alt](https://www.hello-algo.com/chapter_graph/graph_traversal.assets/graph_dfs.png)

**算法实现：**这种“走到尽头再返回”的算法范式通常基于递归来实现。与广度优先遍历类似，在深度优先遍历中，我们也需要借助一个哈希集合`visited`来记录已经被访问的节点，以避免重复访问节点

```c++
void dfs(GraphAdjList &graph, unordered_set<Vertex*> &visited, vector<Vertex*> &res, Vertex * vet){
    res.push_back(vet); // 记录访问顶点
    visited.emplace(vet); // 标记该顶点已被访问
    for(Vertex* adjVet : graph.adjList[vet]){
        if(visited.count(adjVet))
            continue; // 跳过已被访问的顶点
        // 递归访问邻接顶点
        dfs(graph, visited, res, adjVet);
    }
}

// 深度优先遍历
vector<Vertex*> graphDFS(GraphAdjList &graph, Vertex* stratVet){
    vector<Vertex *> res;
    unordered_set<Vertex* > visited;
    dfs(graph, visited, res, startVet);
    return res;
}
```

算法流程示意图如上：

- **直虚线（蓝色）代表向下递推**，表示开启了一个新的递归方法来访问新顶点
- **曲虚线（橙色）代表向上回溯**，表示此递归方法已经返回，回溯到了开启此方法的位置

**复杂度分析**

- **时间复杂度：**所有顶点都会被访问1次，使用$O(V)$时间，所有边都会被访问两次，使用$O(2E)$时间，总体使用$O(V+E)$时间
- **空间复杂度：**列表`res`，哈希集合`visited`顶点数量最多为$V$，递归深度最大为$V$，因此使用$O(V)$空间

## 排序算法

### 排序算法概述

排序算法(sorting algorithm)用于对一组数据按照特定顺序进行排列。其有着广泛的应用，因为有序数据通常能够被更高效地查找、分析和处理

#### 评价维度
**运行效率：** 我们期望排序算法的时间复杂度尽量低，且总体操作数量较少（时间复杂度中的常数项变少）

**就地性：** 顾名思义，原地排序通过在原数组上直接操作实现排序，无需借助额外的辅助数组，节省内存。通常情况下，原地排序的数据搬运操作较少，运行速度也更快

**稳定性：** 在完成排序后，相等元素在数组中的相对顺序不发生改变。这是多级排序场景的必要条件，非稳定排序可能会导致输入数据的有序性丧失

```plaintext
# 输入数据是按照姓名排序好的
# (name, age)
  ('A', 19)
  ('B', 18)
  ('C', 21)
  ('D', 19)
  ('E', 23)

# 假设使用非稳定排序算法按年龄排序列表，
# 结果中 ('D', 19) 和 ('A', 19) 的相对位置改变，
# 输入数据按姓名排序的性质丢失
  ('B', 18)
  ('D', 19)
  ('A', 19)
  ('C', 21)
  ('E', 23)
```

**自适应性：** 自适应排序能够利用输入数据已有的顺序信息来减少计算量，达到更优的时间效率。自适应排序算法的最佳时间复杂度通常优于平均时间复杂度

**是否基于比较：** 基于比较的排序依赖比较运算符来判断元素的相对顺序，从而排序整个数组，理论最优时间复杂度为$O(nlogn)$，而非比较排序不适用比较运算符，时间复杂度可以达到$O(n)$，但其通用性相对较差

#### 理想排序算法

运行快、原地、稳定、自适应、通用性好，但是迄今为止都未发现兼具以上特性的排序算法

### 选择排序(selection sort)

选择排序的工作原理比较简单：开启一个循环，每轮从未排序的区间内选择最小的元素，将其放到已排序区间的末尾

#### 算法流程

设数组长度为n，其大致流程如下：
1. 初始状态下，所有元素未排序，未排序的索引区间为[0,n-1]
2. 选取区间[0,n-1]中的最小元素，将其与索引0处的元素交换，完成后，数组的前1个元素已经排序
3. 选取区间[1,n-1]中的最小元素，将其与索引1处的元素交换，完成后，数组的前2个元素已经排序
4. 以此类推，经过n-1轮选择与交换后，数去前n-1个元素已排序
5. 仅剩的一个元素必定是最大元素，无需排序，数组排序完成

可以看这个演示链接：https://www.hello-algo.com/chapter_sorting/selection_sort.assets/selection_sort_step1.png

在代码中，我们用k来记录未排序区间内的最小元素

```c++
void selectionSort(vector<int> &nums){
	int n = nums.size();
	//外部循环，未排序区间为[i,n-i]
	for(int i = 0; i < n; i++){
         //定义k用于记录最小元素的索引
		int k =j;
         //内循环：找到未排序区间内的最小元素
		for(int j= i+1, j < n; j++){
            if(nums[i]<nums[j])
                k=j;//记录最小元素的索引
        }
        //将该最小元素与未排序区间的首个元素交换
        swap(nums[i],nums[j]);
	}
}
```

#### 算法特性

- **时间复杂度为$O(n^2)$、非自适应排序**：外循环共n-1轮，第一轮的未排序区间长度为n，最后一轮的未排序区间长度为2，各轮外循环分别包含n,n-1……,3,2轮内循环，求和为$\frac{(n-)(n+2)}{2}$
- **空间复杂度为$O(1)$、原地排序**：指针i和j使用常数大小的额外空间
- **非稳定排序**：因为元素`nums[i]`有可能被交换至与其相等的元素的右边，导致两者的相对顺序发生改变


### 冒泡排序（Bubble sort）

冒泡排序通过连续地比较与交换相邻元素实现排序，整个过程就像气泡从底部升到顶部一样

其可以利用元素交换操作来模拟：从数组最左端向右遍历，依次比较相邻元素的大小，如果"左元素">“右元素”，就交换二者，遍历完成后，最大的元素会被移动到数组的最右端

#### 算法流程

设数组的长度为n，冒泡排序的步骤如图
![图片alt](https://www.hello-algo.com/chapter_sorting/bubble_sort.assets/bubble_sort_overview.png)
1. 首先对n个元素执行“冒泡”，将数组的最大元素交换至正确位置
2. 对剩余n-1个元素执行“冒泡”，将第二大的元素交换至正确位置
3. 以此类推，经过n-1轮“冒泡”后，前n-1大的元素都被交换至正确位置
4. 仅剩的一个元素必定是最小元素，无需排序，因此数组排序完成

代码示例如下

```c++
void bubbleSort(vector<int> &nums){
	for(int i = nums.size()-1; i > 0; i--){
		for(int j = 0; j < i;j++){
			if(nums[j]>nums[j+1]){
				swap(nums[j],nums[j+1]);
			}
		}
	}
}
```

#### 效率优化

我们发现，如果某轮“冒泡”中没有执行任何交换操作，说明数组已经完成排序，可以直接返回结果，因此我们可以增加一个标志位`flag`来监测这种情况，一旦出现就立即返回，总而减小时间复杂度

经过优化，冒泡排序的最差时间复杂度和平均时间复杂度仍为$O(n^2)$，但当输入的数组完全有序时，可以达到最佳时间复杂度$O(n)$

```c++
void bubbleSortWithFlag(vector<int> &nums){
	for(int i = nums.size()-1; i > 0; i--){
		bool flag = false; //注意这里flag的定义位置在外循环里，内循环外
		for(int j = 0; j < i; j++){
			if(nums[j]>nums[j+1]){
				swap(nums[j],nums[j+1]);
				flag=true;
			}
		}
		if(flag=flase)
			break; //此轮“冒泡”未交换任何元素，直接跳出循环
	}
}
```

#### 算法特性
- **时间复杂度为$O(n^2)$、自适应排序**：各轮冒泡遍历数组长度为n-1,n-2,……,1，总和为(n-1)n/2，引入`flag`优化后，最佳时间复杂度可以达到$O(n)$
- **空间复杂度为$O(1)$，原地排序**：指针i和j使用常数大小的额外空间
- **稳定排序**：冒泡排序中遇到相等元素不交换

### 插入排序（insertion sort）

插入排序是一种简单的排序算法，它的工作原理与手动整理一副牌非常相似。我们在未排序区间选择一个基准元素，将该元素与其左侧已排序区间的元素逐一比较大小，并将该元素插入到正确的位置。

下图展示了数组插入元素的操作流程，设基准元素为`base`，我们需要将从目标索引到`base`之间的所有元素向右移动一位，然后将`base`赋值给目标索引
![图片alt](https://www.hello-algo.com/chapter_sorting/insertion_sort.assets/insertion_operation.png)

#### 算法流程

插入排序的整体流程如下：
1. 初始状态下，我们认为数组的第1个元素已经完成排序
2. 选取数组的第2个元素作为`base`，将其插入到正确位置后，数组的前2个元素已经正确排序
3. 选组第3个元素作为`base`，将其插入到正确位置后，数组的前3个元素已经正确排序
4. 以此类推，在最后一轮中，选取一个元素作为`base`，将其插入到正确位置后，所有元素均已正确排序

![图片alt](https://www.hello-algo.com/chapter_sorting/insertion_sort.assets/insertion_sort_overview.png)

示例代码如下：

```c++
void insertionSort(vector<int> &nums){
	for(int i = 1; i < nums.size(); i++){
		int base = nums[i],j = i - 1;
		// 内循环，将base插入到已排序区间[0,i-1]中的正确位置
		while(j >= 0 && nums[j] > base){// 这里是从后往前比较
			nums[j+1] = nums[j];//将nums[j]向右移动一位
			j--;
		}
		nums[j+1] = base; //将base赋值到正确位置
	}
}
```

#### 算法特性

- **时间复杂度为$O(n^2)$、自适应排序**：在最差情况下，每次插入操作分别需要循环1,2,...,n-1次，求和得到(n-1)(n)/2，因此时间复杂度为$O(n^2)$，在遇到有序数据时，插入操作会提前终止，当输入数组完全有序时，插入排序达到最佳时间复杂度$O(n)$，其外层循环所导致的时间复杂度，内层循环的时间复杂度为$O(1)$
- **空间复杂度为$O(1)$、原地排序**：指针i和j使用常数大小的额外空间
- **稳定排序**：在插入操作过程中，我们会将元素插入到相等元素的右侧，不会改变它们的顺序

#### 插入排序的优势

插入排序的时间复杂度为$O(n^2)$，而我们即将学习的快速排序的时间复杂度为$O(nlogn)$，尽管插入排序的时间复杂度更高，但在数据量较小的情况下，插入排序通常更快。

这个结论与线性查找和二分查找适用情况的结论类似，快速排序这类$O(nlogn)$的算法属于基于分治策略的排序算法，往往包含更多单元计算操作，而在数据量较小时，$n^2,nlogn$的数值比较接近，复杂度不占主导地位，每轮中的单元操作数量起到决定性作用。

实际上，许多编程语言（例如Java）的内置排序函数采用了插入排序，大致思路为：对于长数组，采用基于分治策略的排序算法，例如快速排序；对于短数组，直接使用插入排序

虽然冒泡排序、选择排序、插入排序的时间复杂度都为$O(n^2)$，但在实际情况下，插入排序的使用频率显著高于冒泡排序和选择排序，主要有以下原因：
- 冒泡排序基于元素交换实现，需要借助一个临时变量，共涉及3个单元操作；插入排序基于元素赋值实现，仅需1个单元操作。因此，冒泡排序的计算开销通常比插入排序更高。
- 选择排序在任何情况下的时间复杂度都为$O(n^2)$，如果给定一组部分有序的数据，插入排序通常比选择排序效率更高。
- 选择排序不稳定，无法应用于多级排序

### 快速排序(quick sort)

快速排序是一种基于分治策略的排序算法，运行高效，应用广泛

快速排序的核心操作是“哨兵划分”，其目标是选择数组中的某个元素作为“基准数”，将所有小于基准数的元素移到其左侧，而大于基准数的元素移到其右侧。

哨兵划分的流程如下：
1. 选择数组最左端元素作为基准数，初始化两个指针i和j分别指向数组的两端
2. 设置一个循环，在每轮中使用i（j）分别寻找第一个比基准数大（小）的元素，然后交换这两个元素
3. 循环执行步骤2，直至i和j相遇时停止，最后将基准数交换至两个子数组的分界线

演示链接可以看([11.5  快速排序 - Hello 算法](https://www.hello-algo.com/chapter_sorting/quick_sort/#__tabbed_1_1))


而哨兵划分完成后，原数组就被划分成三个部分：左子数组、基准数、右子数组，且满足“左子数组任意元素$\leq$基准数$\leq$右子数组任意元素”，因此，我们接下来只需对这两个子数组进行排序。（其本质是将一个较长数组的排序问题简化为两个较短数组的排序问题，这也是分支策略的核心）

```c++
int partition(vector<int> &nums, int left, int right){
	//我们以nums[left]为基准数
	int i = left, j = right;
	while(i < j){
		while(i < j && nums[j] >= nums[left])
			j--;//因为我们从右往左找是要找一个比基准数小的，我们一直循环直至找到
		while(i < j && nums[i] <= nums[left])
			i++;
		swap(nums[i],nums[j]);
	}
	swap(nums[i],nums[left]);
	return i;
}
```

#### 算法流程

快速排序的整体流程如下：

1. 首先，对原数组执行一次“哨兵划分”，得到未排序的左子数组和右子数组
2. 然后，对左子数组和右子数组分别递归执行“哨兵划分”
3. 持续递归，直至子数组长度为1时停止，从而完成整个数组的排序

![图片alt](https://www.hello-algo.com/chapter_sorting/quick_sort.assets/quick_sort_overview.png)

示例代码如下：

```c++
void quickSort(vector<int> &nums, int left, int right){
    if(left >= right)// 递归终止条件，当left ≥ right时，意味着当前要处理的子数组长度为1或者为空
        return;
    int pivot = partition(nums, left, right);//
    // 分为两个数组，其中一个数组的操作范围是从最左边到基准数的前一位，也就是[left,pivot-1]，另一个数组的操作范围是从基准数的后一位到最右边，也就是[pivot+1,right]，并且通过递归调用不断将子数组划分为更小的部分并递归排序，最终完成排序。
    qucikSort(nums, left, pivot-1); 
    quickSort(nums, pivot + 1, right);
}
```

#### 算法特性

- **时间复杂度为$O(nlogn)$、非自适应排序**：在平均情况下，哨兵划分的递归层数为$logn$，每层中的总循环数为n（这里的每层指的是哨兵划分的操作，其中我们有双指针i和j从数组），总体使用$O(nlogn)$时间.在最差情况下,每轮哨兵划分操作都将长度为n的数组划分为长度为0和n-1的两个子数组,此时递归层数达到n,每层中的循环数为n,总体的时间复杂度为$O(n^2)$
- **空间复杂度为$O(n)$、原地排序：** 在输入数组完全倒序的情况下，达到最差递归深度n（每次递归调用都需要一些栈空间来保存局部变量，比如函数参数、返回地址等等，栈空间的使用与递归深度有关），使用$O(n)$栈桢空间。排序操作是在原数组上进行的，未借助额外数组
- **非稳定排序：** 在哨兵划分的最后一步，基准数可能会被交换至相等元素的右侧

#### 快速排序为什么快

尽管快速排序的平均时间复杂度与“归并排序”和“堆排序”相同，但通常快速排序的效率更高，主要原因如下：
- 出现最差情况的概率很低：虽然快速排序的最差时间复杂度为$O(n^2)$，没有归并排序稳定，但是在绝大多数情况下，快速排序能在$O(nlogn)$的时间复杂度下运行
- 缓存使用效率高：在执行哨兵划分操作时，系统可以将整个子数组加载到缓存，因此访问元素的效率极高，而像“堆排序”这类算法需要跳跃式地访问元素，缺乏这一特性
- 复杂度的常数系数小：在上述三种算法中，快速排序的比较、赋值、交换等操作的总数量最少，这与“插入排序”比“冒泡排序”更快的原因类似

### 归并排序(merge sort)

归并排序是一种基于分支策略的排序算法，包含下图所示的“划分”和“合并”阶段

![图片alt](https://www.hello-algo.com/chapter_sorting/merge_sort.assets/merge_sort_overview.png)

**划分阶段**通过递归不断地将数组从中点处分开，将长数组的排序问题转换为短数组的排序问题
**合并排序**则是在子数组的长度为1时终止划分，开始合并，持续地将左右两个较短的有序数组合并为一个较长的有序数组，直至结束

#### 算法流程

前面提到，归并排序的算法分为“划分”和“合并”两个阶段，划分阶段的操作如下：

1. 计算数组中点`mid`，递归划分左子数组（区间`[left,mid]`）和右子数组（区间`[mid+1,right]`）
2. 递归执行步骤1，直至子数组区间长度为1时终止

合并阶段则是从底至顶将左子数组和右子数组合并为一个有序数组。并且需要注意的是，从长度为1的子数组开始合并，合并阶段中的每个子数组都是有序的，其操作如下：

1. 首先根据要合并的两个子数组的元素总个数创建一个合适大小的临时数组`tmp`用于存放
2. 设置三个索引变量，`i`指向左子数组的起始位置，`j`指向右子数组的其实位置，`k`指向临时数组`tmp`的起始位置
3. 当左子数组和右子数组都还有元素时，比较两个子数组当前指向的元素大小，（即`nums[i]`,`nums[j]`)，如若`nums[i]`较小就把它放入临时数组tmp中，并且使i++，k++；接着重复这个比较与放入操作，不断将较小元素一次放入`tmp`数组
4. 当左子数组和右子数组中有一个没有元素，一个剩余元素时，就把剩余元素依次复制到临时数组`tmp`中。
5. 最后将临时数组`tmp`里合并好的有序元素按顺序复制回原数组`nums`中索引`left`开始的对应位置，完成合并操作。

演示链接如下：https://www.hello-algo.com/chapter_sorting/merge_sort/#1161

观察发现，归并排序与二叉树后序遍历的递归顺序是一致的：

- **后序遍历**：先递归左子树，再递归右子树，最后处理根节点
- **归并排序**：先递归左子数组，在递归右子数组，最后处理合并

归并排序的代码示例如下，`nums`的待合并区间为`[left,right]`，而`tmp`的对应区间为`[0,right-left]`

```c++
void merge(vector<int> &nums, int left, int mid, int right){
	//左子数组的区间为[left,mid]，右子数组的区间为[mid+1,right]
    vector<int> tmp(right-left+1);
    int i = left,  j= mid + 1; k = 0;
    while(i <= mid && j <= right){
        if(nums[i] <= nums[j]){
            tmp[k] = nums[i];
            i++;
            k++;
        }
        else{
            tmp[k] = nums[j];
            j++;
            k++;
        }
    }
    //到这里已经有一个数组空了，接下来复制剩余元素
    while(i <= mid){
        tmp[k] = nums[i];
        i++;
        k++;
    }
    while(j <= right){
        tmp[k] = nums[j];
        j++;
        k++;
    }
    // 将临时数组tmp的元素复制回原数组nums的对应区间
    for(k=0; k < tmp.size(); k++){
        nums[left + k] = tmp[k];
    }
}

void mergeSort(vector<int> &nums, int left, int right){
    // 终止条件
    if(left >= right)
        return;
    int mid = left + (right - left)/2;
    mergeSort(nums, left, mid); // 递归左子数组
    mergeSort(nums, mid + 1, right); // 递归右子数组
    // 合并
    merge(nums, left, mid, right); // 注意这里很像二叉树的后序遍历
}

```

#### 算法特性

- **时间复杂度为$O(n logn)$、非自适应排序：** 划分产生高度为$logn$的递归树，每层合并的总操作数量为n，因此总体时间复杂度为$O(nlogn)$
- **空间复杂度为$O(n)$、非原地排序：** 递归深度为$logn$，使用$O(logn)$大小的栈桢空间，而合并操作需要借助辅助数组实现，使用$O(n)$大小的额外空间
- **稳定排序：** 在合并过程中，相等元素的次序保持不变

#### 链表排序

对于链表，归并排序相较于其他算法具有显著优势，其**可以将链表排序任务的空间复杂度优化至$O(1)$**
- **划分阶段**：可以使用“迭代”替代“递归”来实现链表划分工作，从而省去递归使用的栈桢空间
- **合并阶段**：在链表中，节点增删操作仅需改变（引用）指针即可实现，因此合并阶段（将两个短有序链表合并为一个长有序链表）无需创建额外链表

### 堆排序(heap sort)

堆排序(heap sort)是一种基于堆实现的高效排序算法，我们可以利用之前学过的“建堆操作”和“元素出堆操作”来实现堆排序，其大致步骤如下：

1. 输入数组并建立小顶堆，此时最小元素位于堆顶
2. 不断执行出堆操作，依次记录出堆元素，即可得到从小到大排序的序列

虽然上述方法确实可行，但是我们还需要借助一个额外的数组来保存弹出的元素，比较浪费空间。

#### 算法流程

设数组的长度为n，堆排序的步骤如下：

1. 输入数组并建立大顶堆。完成后最大元素位于堆顶
2. 将堆顶元素（第一个元素）与堆底元素（最后一个元素）交换。交换完成后，堆的长度减1（其实就是pop_back让最后一个元素出堆，这个元素是原本的堆顶元素，也就是最大的元素，这时候它放在了最后的位置，已经完成排序），已排序元素数量加1
3. 从堆顶元素开始，从顶到底执行堆化操作(sift down)，完成堆化后，堆的性质得到修复
4. 循环执行第2部和第3步，循环n-1轮后，即可完成数组排序

演示链接：[11.7  堆排序 - Hello 算法](https://www.hello-algo.com/chapter_sorting/heap_sort/#__tabbed_1_1)

需要注意的是，由于我们提取最大元素的时候相当于元素出堆，需要从顶向下堆化，并且由于堆的长度会随着提取最大元素而减小，我们需要给sift_down()函数添加一个长度参数n，用于指定堆的当前有效长度，代码实现如下：

```c++
// 堆的长度为n，从节点i开始，从顶至底堆化
void siftDown(vector<int> &nums, int n, int i){// nums是操作的数组，n是堆的长度，i是堆化起始节点的指标
	while(true){
		int l = 2 * i + 1;
		int r = 2 * i + 2;
		int ma = i;
		if(l < n && nums[l] > nums[ma]){
			ma = l;
		}
		if(r < n && nums[r] > nums[ma]){
			ma = r;
		}
         
         if (ma == i) break; // 如果当前节点已经是最大值，退出循环
		swap(nums[i], nums[ma]);
		i = ma;
	}
}

void heapsort(vector<int> &nums){
	// 这里是建堆操作
	for(int i = nums.size()/2 -1; i >= 0; --i){ // 这里nums.size()/2-1是最后一个非叶节点的索引，原理是由最后一个叶节点求其父节点 
		siftDown(nums, nums.size(), i);// 直接在nums数组上操作把它变成了一个表示堆的数组
	}
	// 这里是从堆中提取最大元素，循环n-1轮
	for(int i = nums.size() - 1; i > 0; --i){
		// 交换根节点与最右叶结点（交换首元素与尾元素）
		swap(nums[0], nums[i]);
		// 以根节点为起点，从顶至底进行堆化
		siftDown(nums, i, 0);
	}
}
```

#### 算法特性

- **时间复杂度为$O(nlogn)$、非自适应排序**：建堆操作的时间复杂度为$O(n)$，从堆中提取最大元素的时间复杂度为$O(logn)$，共循环n-1轮，故提取最大元素（包括堆化操作）的时间复杂度为$O(nlogn)$，所以总的时间复杂度为$O(n)+O(nlogn)=O(nlogn)$。而**非自适应排序**的意思是执行过程不会根据数据的初始有序程度进行优化或调整，也即无论输入数据是否接近有序，其执行流程和时间复杂度都保持一致
- **空间复杂度为$O(1)$、原地排序**：几个指针变量都使用$O(1)$空间；元素交换和堆操作都是在原数组上进行的，并没有额外使用另一个数组保存
- **非稳定排序**：在交换堆顶元素和堆底元素时，相等元素的相对位置可能会发生变化

---
前面集中排序算法都属于“基于比较的排序算法”，它们通过比较元素间的大小来实现排序，此类排序算法的时间复杂度无法超越$O(nlogn)$，接下来我们将探讨集中“非比较排序算法”，它们的时间复杂度可以达到线性阶

### 桶排序(bucket sort)

桶排序是分治策略的一个典型应用，它通过设置一些具有大小顺序的桶，每个桶对应一个数据范围，将数据平均分配到各个桶中；然后在每个桶内分别执行排序；最后按照桶的顺序将所有数据合并

#### 算法流程

我们考虑一个长度为n的数组，其元素是范围[0,1)内的浮点数，排序流程如下图所示

![图片alt](https://www.hello-algo.com/chapter_sorting/bucket_sort.assets/bucket_sort_overview.png)

1. 初始化k个桶，将n个元素分配到k个桶中
2. 对每个桶分别执行排序（这里采用编程语言的内置排序函数）
3. 按照桶从小到大的顺序合并结果

代码示例如下：

```c++
void bucketSort(vector<float> &nums){
	// 这里初始化 k = n/2个桶，预期向每个桶分配2个元素
	int k = nums.size() / 2;
    vector<vector<float>> buckets(k);
    
    // 将数组元素分配到各个桶中
    for(float num : nums){
        //输入数据范围为[0,1)，使用num * k 映射索引范围[0,k-1)
        int i = num * k; // 由于i是个整数，这里在乘积是浮点数的时候会发生隐式类型转换
        
        buckets[i].push_back(num)
    }
    // 对各个桶执行排序
    for<vector<floar> & bucket : buckets{
        sort(bucket.begin(), bucket.end());
    } 
    // 遍历桶合并结果
    int i = 0;
    for(vector<float> &bucket : buckets){
        for (float num : bucket){
            nums[i++] = num;
        }
    }
}
```

#### 算法特性（这一部分我感觉自己不太理解）

桶排序适用于处理体量很大的数据，例如 输入数据包含100万个元素，由于空间限制，系统内存无法一次性加载所有数据。此时，就可以将数据分成1000个桶，然后分别对每个桶进行排序，最后将结果合并

- **时间复杂度为$O(n+k)$**：假设元素在各个桶内平均分布，那么每个桶内的元素数量为$\frac{n}{k}$。假设排序单个桶使用$O(\frac{n}{k}log\frac{n}{k})$时间，则排序所有桶使用$O(nlog\frac{n}{k})$时间，当桶数量$k$比较大时，时间复杂度会趋向于$O(n)$，合并结果时需要遍历所有桶和元素，花费$O(n+k)$时间。在最差情况下，所有数据都被分配到同一个桶中，且排序该桶使用$O(n^2)$时间
- **空间复杂度为$O(n+k)$、非原地排序：**需要借助k个桶和总共n个元素的额外空间
- 桶排序是否稳定取决于排序桶内元素的算法是否稳定

#### 如何实现平均分配

桶排序的时间复杂度理论上可以达到$O(n)$，**关键在于将元素均匀分配到各个桶中**，因为实际数据往往不是均匀分布的。例如，我们想要将淘宝上的所有商品按价格范围平均分配到10个桶中，但商品价格分布不均，低于100元的非常多，而高于1000元的非常少。如若我们将价格区间平均划分为10个，那么各个桶中的商品数量差距会非常大

为了实现平均分配，我们可以先设定一条大致的分界线，将数据粗略地分到3个桶中。分配完毕后，再将商品较多的桶继续划分为3个桶，直至所有桶中的元素数量大致相等，如下图所示

![图片alt](https://www.hello-algo.com/chapter_sorting/bucket_sort.assets/scatter_in_buckets_recursively.png)

其本质是创建一棵递归树，目标是让叶节点的值尽可能的平均。（当然不一定要每轮都将数据划分为3个桶）

如果我们提前知道商品价格的概率分布，也可以根据数据的概率分布来设置每个桶的价格分界线，值得注意的是，数据分布并不一定需要特意统计，也可以根据数据特点采用某种概率模型进行近似。比如正态分布

### 计数排序(counting sort)

计数排序通过统计元素的数量来实现排序，通常应用于整数数组

#### 简单实现

我们先来看一个简单的例子，给定一个长度为n的数组`nums`，其中的元素都是“非负整数”，计数排序的整体流程如下图所示

![图片alt](https://www.hello-algo.com/chapter_sorting/counting_sort.assets/counting_sort_overview.png)

1. 遍历数组，找出其中最大的数，记为m，然后创建一个长度为m+1的辅助数组`counter`
2. 借助`counter`统计`nums`中各数字的出现次数，其中`counter[num]`对应数字`num`的出现次数。统计方法其实就是，遍历`nums`（设当前数组为`num`），每轮将`counter[num]`增加1即可
3. 由于`counter`的各个索引是天然有序的，因此相当于所有数字已经排序好了。接下来，我们遍历`counter`，根据各数字出现次数从小到大的顺序填入`nums`即可

其代码示例如下：

```c++
// 这只是一个简单实现，无法用于排序对象
void countingSortNaive(vector<int> &nums){
	// 第一步遍历找到数组中的最大数
    int m =0;
    for(int num : nums){
        m = max(m,num);
    }
    // 统计各数字的出现次数，这里创建了一个容量为m+1的数组，赋初值为0
    vector<int> counter(m+1,0);
    for(int num : nums){
        counter[num]++;
    }
    // 遍历counter，将各元素填入原数组nums
    int i = 0;
    for(int num = 0; num < m + 1; num++){
        for(int j = 0; j < counter[num]; j++, i++){
            nums[i] = num;
        }
    }
}
```

#### 完整实现

我们前面提到，给出的只是计数排序的一个简单实现，如果输入数据是对象，这个简单失效就会失效。比如我们假设输入数据是商品对象，我们想按照商品价格（类的成员变量）对商品进行排序，而上述算法只能给出价格的排序结果

那么我们如何才能得到原数据的排序结果呢？我们可以首先计算`counter`的“前缀和”。顾名思义，即索引`i`处的前缀和`perfix[i]`等于数组前`i`个元素之和(注意这里的`counter`数组的元素`counter[j]`记录的是j在原来的数据中的个数)：
$$
\text{prefix}[i]=\sum_{j=0}^i\text{counter}[j]
$$
**前缀和是具有明确意义的，`prefix[num]-1`代表了元素`num`在结果数组`res`中最后一次出现的索引**，我们可以这样考虑，$\text{prefix}[i]=\sum_{j=0}^i\text{counter}[j]$记录的是所有小于等于j的数据的个数，而在`res`数组中又是从小到大按顺序排序的，`prefix[num]`记录的就是所有小于等于num的数据的个数，而数组的索引是从0开始，所以`prefix[num]-1`记录的自然就是`num`在结果数组`res`中最后一次出现的索引。

这个信息非常的关键，因为它告诉我们各个元素应该出现在结果数组的哪个位置上。接下来，我们倒序遍历原数组`nums`（也即最初的那个待排序的数组）的每个元素`num`，在每轮迭代中执行以下两步：

1. 将`num`填入数组`res`的索引`prefix[num]-1`处
2. 令前缀和`prefix[num]`减小1，从而得到下次放置num的索引

遍历完成后，数组`res`中就是排序号的结果，最后使用`res`覆盖原数组`nums`即可

演示流程：https://www.hello-algo.com/chapter_sorting/counting_sort/#__tabbed_2_1

代码示例如下：

```c++
// 这是一个完整实现，可以排序对象，并且是稳定排序
void countingSort(vector<int> &nums){
    //第一步仍然是一样的，找到数组中的最大元素m，这是为了构建后续的counter数组
    int m = 0;
    for(int num : nums){
        m = max(m, num)
    }
    // 第二步创建counter数组，并统计各个数字的出现次数
    vector<int> counter(m+1,0);
    for(int num : nums){
        counter[num]++;
    }
    
    // 第三步求counter的前缀和，这里和描述不同的是，我们并未创建一个新的数组prefix用于保存前缀和，而是直接在counter数组的基础上进行操作
    for(int i = 0; i < m; i++){
        counter[i + 1] = counter[i + 1] + counter[i];
    }
    
    // 第四步是倒序遍历nums数组，将结果填入结果数组res
    // 初始化res数组用于记录结果
    int n = nums.size();
    vector<int> res(n);
    for(int i = n - 1;i >= 0; i--){
        int num = nums[i];
        res[counter[num]-1]=num;
        counter[num]--;
    }
    
    // 最后一步，使用结果数组res覆盖原数组nums
    num = res;
}
```

#### 算法特性

- **时间复杂度为$O(n+m)$、非自适应排序：** 涉及遍历`nums`和遍历`counter`，它们都使用线性时间。一般情况下$n\gg m$（m是`nums`数组中的最大元），时间复杂度趋向于$O(n)$
- **空间复杂度为$O(n+m)$、非原地排序：** 借助了长度分别为n和m的数组`res`和`counter`
- **稳定排序**：由于向`res`中填充元素的顺序是“从右向左”的，因此倒序遍历`nums`可以避免改变相等元素之间的相对位置，从而实现稳定排序。实际上，正序遍历`nums`也可以得到正确的排序结果，但是结果是非稳定的

#### 局限性

- **计数排序只能适用于非负整数**，我们其实在操作过程中也能体会到，原来的`nums`数组中的数据`num`后来是作为`counter`数组的索引的。如果想用其他类型的数据，需要确保这些数据可以转换为非负整数，并且在转换过程中不能改变各个元素之间的相对大小关系
- **基数排序适用于数据量大单数据范围较小的情况**，比如如果最大元m过大，就会占用过多空间，而当$n\gg m$时，计数排序使用$O(m)$时间，可能比$O(nlogn)$的排序算法还要慢

### 基数排序(radix sort)

上一节我们介绍了计数排序，它适用于数据量n较大但范围m较小的情况假设我们需要对$n=10^6$个学号进行排序，而学号又是一个八位数字，这意味着数据范围$m=10^8$非常大，使用计数排序需要分配大量的内存空间，而基数排序可以避免这种情况

基数排序的核心思想和计数排序一致，也是通过统计个数来实现排序。在此基础上，基数排序利用数字各位之间的递进关系，依次对每一位进行排序，从而得到最终的排序结果

#### 算法流程

以学号数据为例，假设数字的最低位是第1位，最高位是第8位，基数排序的流程如下图所示：

![图片alt](https://www.hello-algo.com/chapter_sorting/radix_sort.assets/radix_sort_overview.png)

1. 初始化位数k=1
2. 对学号的第k位执行“计数排序”。完成后，数据会根据第k位从大到小排序
3. 将k增加1，然后返回步骤2，继续迭代，直到所有位都排序完成后结束

>这里也是有说法的，因为我们知道，对数排序决定性因素肯定是更高位，所以我们从低位到高位逐渐完成排序，确保这个特性得以满足

而对于一个d机制的数字x，要获取其第k位$x_k$，我们可以使用以下计算公式：
$$
x_k = \big[\frac{x}{d^{k-1}}\big]\text{mod}\ d
$$
其中$[a]$表示对浮点数a向下取整，$\text{mod}\ d$表示对d取模（取余）。对于学号数据，$d=10$且$k \in [1,8]$，此外，我们需要小幅修改计数排序的代码，使之可以根据数字的第k位进行排序：

```c++
// 获取元素num的第k位，其中exp = 10^(k-1)
int digit(int num, int exp){
	return (num/exp) % 10;
}

void countingSortDigit(vector<int> &nums, int exp){
    //因为十进制的范围为0-9，因此需要长度为10的桶数组
    vector<int> counter<10,0>;
    int n = nums.size();
    for(int i = 0; i < n; i++){
        int d = digit(nums[i], exp);
        counter[d]++;
    }
    
    for(int i = 1; i < 10; i++){
        counter[i] += counter[i-1];
    }
    
    vector<int> res(n,0);
    for(int i = n-1; i>=0; i--){
        int d = digit(nums[i], exp);
        int j = counter[d] - 1;
        res[j] = nums[i];
        counter[d]--;
    }
    
    for(int i = 0; i < n; i++)
        nums[i] = res[i];
}

void radixSort(vector<int> &nums){
    int m =*max_element(nums.begin(),nums.end());
    for(int exp = 1; exp <= m; exp *= 10)
        countingSortDigit(nums,exp);
}
```



#### 算法特性

相较于计数排序，基数排序适用于数值范围较大的情况，但前提是数据必须可以表示为固定位数的格式，且位数不能过大。例如浮点数不适合使用基数排序，因为其位数k过大，可能导致时间复杂度$O(nk) \gg O(n^2) $

- **时间复杂度为$O(nk)$、非自适应排序：**设数据量为n，数据为d进制，最大位数为k，则对某一位执行计数排序使用$O(n+d)$时间，排序所有k位使用$O((n+d)k)$时间。通常情况下，d和k都相对较小，时间复杂度趋向$O(n)$
- **空间复杂度为$O(n+d)$、非原地排序：**与计数排序相同，基数排序需要借助长度为n和d的数组`res`和`counter`
- **稳定排序：** 当计数排序稳定时，基数排序也稳定；当计数排序不稳定时，基数排序无法保证得到正确的排序结果。





## 中缀表达式转后缀表达式+后缀表达式的计算

中缀表达式：操作符以中缀形式位于运算数中间（比如3+2），是我们日常通用的算术和逻辑公式表示方法

后缀表达式：又称逆波兰式，即操作符以后缀形式位于两个运算数之后（比如3+2的后缀表达式即3 2 +）

前缀表达式：又称波兰式，操作符以前缀形式位于两个运算数前（如3+2的前缀表达形式即+ 3 2 ）

中缀表达式往往需要使用括号将操作符和对应的操作数括起来，用于指示运算的次序，虽然中缀表达式更适合人类的思维和运算习惯，但并不适用于计算机，适用于计算机的是后缀表达式

与中缀表达式不同，后缀表达式并不需要使用括号来标识操作符的优先级，其按操作符从左到右出现的顺序依次执行（不考虑运算符之间的优先级）

那么**中缀表达式如何转后缀表达式**呢？

其方法是从左至右遍历中缀表达式各个字符（需要准备一个字符栈来存储操作符和括号）：

1. 如若字符为**运算数**：直接送入后缀表达式
2. 字符为**左括号**：直接入栈（左括号入栈后优先级降至最低）
3. 字符为**右括号**：直接出栈，并将出栈字符依次送入后缀表达式，直至栈顶字符为左括号（左括号也要出栈，但是不送入后缀表达式）
4. 字符为**操作符**：若栈空则直接入栈，若栈非空则先判断栈顶操作符，如果栈顶操作符优先级低于该操作符，则该操作符入栈；否则需要一直出栈并将出栈字符一次送入后缀表达式，直至栈空或者栈顶操作符优先级（如果操作符优先级和栈顶操作符等同，也要继续出栈直至操作符优先级高于目前的栈顶操作符）低于该操作，该操作符再入栈。也即**只要*栈空*或者*优先级高于栈顶操作符*即可将该操作符入栈，反正也就是保持栈顶操作符的优先级是最高的**

5. 重复以上步骤直至遍历完成中缀表达式，接着判断字符栈是否为空，非空则直接出栈，并将出栈字符依次送入后缀表达式

比如`2*(3+5)+7/1-4`转化为后缀表达式

转化完之后为`2 3 5 + * 7 1 / + 4 -`

**后缀表达式的计算：** 后缀表达式在计算时我们需要**从左至右依次遍历后缀表达式各个字符**（需要准备一个运算栈存储运算数和操作结果）

1. 字符为**运算数：**直接入栈
2. 字符为**操作符：**连续出栈两次，使用出栈的两个数据进行相应计算，并将计算结果入栈（比如第一个出栈的运算数为a，第二个出栈的运算数为b，此时的操作符为`-`，则计算为`b-a`，注意a和b的顺序不能反，并将结果入栈）
3. 重复以上步骤直至遍历完成后缀表达式，最后栈中的数据就是中缀表达式的计算结果

举个例子：`2 3 5 + * 7 1 / + 4 -`的计算

## 并查集

并查集是一种数据结构，用于处理一些不相交集合的合并和查询问题（即所谓的并、查），其主要支持两个操作：

- 查找(Find)：查找某个元素属于哪个集合
- 合并(Union)：将两个集合合并成一个集合

并查集有着广泛的应用场景，多见于动态连通性问题，比如：网络中的连通问题、判断图中的连通分量、最小生成树算法（如Kruskal算法）中的边的合并和查询

### 并查集的基本实现

并查集可以用一个数组来表示，通常称为`parent`数组，每个元素的父节点记录在`parent`数组中，如果`parent[i] == i`就表示`i`是根节点，自己是自己的父节点

并查集的主要作用是求连通分支数（如果一个图中所有点都存在可达关系，比如直接或间接相连），则这个图的连通分支数为1；如果此图有两大子图各自全部可达，则此图的连通分支数为2

核心思想是：

1. 查找(`Find`)：查找元素的根节点，如果一个元素的父节点不是自己，就递归查找其父节点。为了优化查询过程我们通常会用到路径压缩技术
2. 合并(`Union`)：将两个集合合并。在合并时，可以将一个根节点的树挂到另一个根节点下，合并时常用**按秩合并(Union by Rank)**或**按大小合并(Union by Size)**来优化

基本数据结构如下：

```c++
class Disjointset{
private:
    vector<int> parent;  // 用来存储每个节点的父节点
    vector<int> rank; // 用来存储每个节点的秩（树的深度）
    
public:
    DisjointSet(int n){
        parent.resize(n); 
        rank.resize(n,0); // 初始时秩都设置为0
        for(int i = 0; i < n; ++i){
            parent[i] = i;// 将每个元素的父节点指向自己
        }
        
    }
    
    // 查找操作，并路径压缩
    int find(int x){
        if(parent[x] != x){
            parent[x] = find(parent[x]); // 递归查找并进行路径压缩
        }
        return parent[x];
    }
    
    // 合并操作，按秩合并
    void unionSets(int x, int y){
        int rootX = find(x);
        int rootY = find(y);
        
        if(rootX != rootY){
            if(rank[rootX] > rank[rootY]){
                parent[rootY] = rootX;
            }
            else if (rank[rootX] < rank[rootY]){
                parent[rootX] = rootY;
            }
            else{//秩相同的情形
                parent[rootY] = rootX; //选一个作为根节点
                rank[rootX]++; //这里需要尤其注意，作为根节点的这个节点的rank要加1
            }
        }
    }
};
```

### 时间复杂度分析

- 查找操作（`find`）的时间复杂度**接近常数时间**，因为路径压缩的作用。论上，查找的复杂度是 **O(α(n))**，其中 `α(n)` 是阿克曼函数的反函数
- 合并操作(`unionSets`)的时间复杂度也是**O(α(n))**，因为每次查找和合并的过程都需要查找根节点，然后进行秩合并，整体非常高效

### 并查集的效率提升技巧

1. **路径压缩**
2. **Union by rank**
3. **Union by size**

​	对于**Union by size**，其原理是在合并时将较小的树挂到较大的树下，从而避免形成深度过大的树，具体做法是用一个数组`size[]`来记录每个根节点的树的大小

```c++
void unionSets(int x, int y){
    int rootX = find(x);
    int rootY = find(y);
    
    if(rootX != rootY){
        if(size[rootX] > size[rootY]){
            parent[rootY] = parent[rootX];
            size[rootX] = size[rootX] + size[rootY];
        }else{
            parent[rootX] = parent[rootY];
            size[rootY] = size[rootY] + size[rootX];
        }
    }
}
```

## 动态规划（DP）

### 动态规划问题特性

动态规划是通过子问题分解来解决原问题的，子问题分解是一种通用的算法思路，在分治、动态规划、回溯中的侧重点不同

- 分治算法递归地将原问题划分为多个相互独立的子问题，直至最小子问题，并在回溯中合并子问题的解，最终得到原问题的解
- 动态规划也对问题进行递归分解，但与分治算法的主要区别是，动态规划中的子问题是相互依赖的，在分解过程中会出现许多重叠子问题
- 回溯算法则在尝试和回退中穷举所有可能的解，并通过剪枝避免不必要的搜索分治。原问题的解由一系列决策步骤构成，我们可以将每个决策步骤之前的子序列看作一个子问题

#### 最优子结构

我们先来看一个问题：**爬楼梯最小代价**

给定一个楼梯，你每步可以上 1 阶或者 2 阶，每一阶楼梯上都贴有一个非负整数，表示你在该台阶所需要付出的代价。给定一个非负整数数组 cost ，其中 cost[i] 表示在第 i 个台阶需要付出的代价，cost[0] 为地面（起始点）。请计算最少需要付出多少代价才能到达顶部？

如图所示，若第1、2、3阶的代价分别为1、10、1，则从地面爬到第3阶的最小代价为2

![图片alt](https://www.hello-algo.com/chapter_dynamic_programming/dp_problem_features.assets/min_cost_cs_example.png)

我们设$dp[i]$为爬到第$i$阶累计付出的代价，由于第$i$阶只可能从$i-1$阶或$i-2$阶走来，因此$dp[i]$只可能等于$dp[i-1]+cost[i]$或$dp[i-2]+cost[i]$，为了尽可能减少代价，我们应该选择两者中较小的那一个，也即
$$
dp[i]=min(dp[i-1],dp[i-2])+cost[i]
$$
这就可以引出最优子结构的含义，原问题的最优解是从子问题的最优解构建得来的。

本题显然具有最优子结构：我们从两个子问题最优解$dp[i-1]$和$dp[i-2]$中挑选出较优的那一个，并用它构建出原问题$dp[i]$的最优解

#### 无后效性

无后效性是动态规划能够有效解决问题的重要特性之一，其定义为：给定一个确定的状态，它的未来发展只与当前状态有关，而与过去经历的所有状态无关

以爬楼梯问题为例，给定状态$i$，它会发展出状态$i+1$和状态$i+2$，分别对应跳1步和跳2步，在作出这两种选择的时候，我们无需考虑状态$i$之前的状态，它们没有影响

然而，如果我们加一个约束情况就不一样了

给定一个共有 n 阶的楼梯，你每步可以上 1 阶或者 2 阶，**但不能连续两轮跳 1 阶**，请问有多少种方案可以爬到楼顶？

![图片alt](https://www.hello-algo.com/chapter_dynamic_programming/dp_problem_features.assets/climbing_stairs_constraint_example.png)

在该问题中，如果上一轮是跳1阶上来的，那么下一轮就必须跳2阶，也就是**下一步不能由当前状态独立决定，还和前一个状态有关**，所以此问题已经不满足无后效性，状态转移方程$ dp[i]=dp[i−1]+dp[i−2] $自然也就失效了，而为了满足约束，我们就不能将$dp[i-1]$直接计入$dp[i]$中

为此，我们需要扩展状态定义：**状态[i,j]**表示处在第$i$阶并且上一轮跳了$j$阶，其中$j \in \left\{1,2\right\}$。此状态定义有效地区分了上一轮跳了一阶还是两阶：

- 当上一轮跳了1阶时，上上一轮只能选择跳2阶，即$dp[i,1]$只能从$dp[i-1,2]$转移过来
- 当上一轮跳了2阶时，上上一轮可以选择跳1阶或2阶，即$dp[i,2]$可以从$dp[i-2,1]$或$dp[i-2,2]$转移过来

如图所示，在该定义下，有状态方程
$$
\begin{cases} 
dp[i,1]= dp[i-1,2]
\\
dp[i,2] = dp[i-2,1]+dp[i-2,2]
\end{cases}
$$
最终返回$dp[n,1]+dp[n,2]$即可

### 最长公共子序列问题

这类问题要求在给定的两个字符串中找到它们的最长公共子序列。子序列的定义是从一个字符串中删除部分字符（也可以不删除），并保持字符的相对顺序，生成新的字符串。最长公共子序列是指两个字符串中的最长的相同子序列

#### 最优子结构

最长公共子序列问题具有最优子结构，这意味着更大的问题可以由较小的子问题递归解决，具体如下
$$
LCS(i,j)=
\begin{cases} 
0,&\text{若i=0或j=0}
\\LCS(i-1,j-1)+1 &若text1[i]=text2[j]
\\max(LCS(i-1,j),LCS(i,j-1))&若text1[i]\ !=text2[j]
\end{cases}
$$
其中$LCS(i,j)$表示text1的前i个字符和text2的前j个字符的最长公共子序列的长度

下面我们考虑最长公共子序列问题的时间复杂度：在使用动态规划方法解决LCS问题时，我们会建立一个二维DP表格，行数为第一个字符串的长度m，列数为第二个字符串的长度n，每个`DP[i][j]`的计算需要常数时间$O(1)$，每个表格有$m*n$个格子，因此总的时间复杂度为$O(m*n)$

其伪代码如下：

    FUNCTION LongestCommonSubsequence(X, Y):
        m = LENGTH(X)
        n = LENGTH(Y)
        dp = ARRAY[m+1][n+1] INITIALIZED TO 0
    
    # 填充 DP 表
    FOR i FROM 1 TO m:
        FOR j FROM 1 TO n:
            IF X[i-1] == Y[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            ELSE:
                dp[i][j] = MAX(dp[i-1][j], dp[i][j-1])
    
    # 回溯找出子序列
    i = m, j = n
    lcs = EMPTY LIST
    WHILE i > 0 AND j > 0:
        IF X[i-1] == Y[j-1]:
            ADD X[i-1] TO lcs
            i = i - 1
            j = j - 1
        ELSE IF dp[i-1][j] > dp[i][j-1]:
            i = i - 1
        ELSE:
            j = j - 1
    
    REVERSE lcs
    RETURN dp[m][n], lcs



我们发现，在利用最优子结构填完DP表之后，我们还需要回溯找出子序列，下面我们详细讲讲回溯操作

回溯的本质是在已经填好的动态规划（DP）表中，从右下角开始逆向寻找，沿着形成最长公共子序列的路径，逐步将公共字符加入结果。

其核心思路如下：

1. **从右下角开始：**
   - 从`dp[m][n]`（X和Y的整个范围）开始回溯
   - 判断当前字符是否在最长公共子序列中
2. **三个判断条件**：
   - 如果字符相等（即`x[i-1]==y[j-1]`），说明`X[i-1],Y[j-1]`是公共子序列的一部分，就将字符加入结果，并移动到左上角的`dp[i-1][j-1]`
   - 如果字符不相等，我们比较`dp[i-1][j]`和`dp[i][j-1]`，如果`dp[i-1][j]`>`dp[i][j-1]`，说明子序列是从`dp[i-1][j]`方向形成的，向上移动（沿i方向），否则向左移动（沿j方向）
3. **终止条件：**回溯停止与`i=0`或`j=0`，也即任意一个序列遍历完成时
4. **反转结果：**因为回溯是从后往前找到子序列，最终结果需要反转

### 最长上升子序列问题

求最长上升子序列（LIS）有三种方法，分别是$O(n^2)$的DP，$O(nlog\ n)$的二分+贪心法，以及$O(nlog\ n)$的树状数组优化的DP

我们先给出最长上升子序列（LIS）的定义：最长上升子序列是指在一个序列中找到一个最长的子序列，使得这个子序列中的元素是严格递增的

比如给定序列`[10,9,2,5,3,7,101,18]`，最长上升子序列可以是`[2,3,7,101]`或`[2,5,7,101]`

#### 解法一：动态规划，$O(n^2)$

我们要求前n个数的最长上升子序列，可以求前n-1个数的最长上升子序列，再跟第n个数进行判断；求前n-1个数的最长上升子序列，可以通过求前n-2个数的最长上升子序列……直到求前1个数的最长总结一下上升子序列，此时LIS当然为1

大致流程如下：

1. 定义`dp[i]`表示以第i个元素结尾的最长上升子序列的长度
2. 初始化`dp`数组为1，因为每个元素本身就是一个长度为1的上升子序列
3. 对于每个元素`nums[i]`，遍历其前面的所有元素`nums[j]`(j<i)，如果`nums[i]>nums[j]`，则更新`dp[i]=max(dp[i],dp[j]+1)`
4. 最终，`dp`数组中的**最大值**即为最长上升子序列的长度

伪代码如下：

```
function LIS(nums):
    n = len(nums)
    dp = [1] * n   // 初始化每个位置的 LIS 长度为 1

    for i from 1 to n-1:
        for j from 0 to i-1:
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)

    return max(dp)
```

#### 解法二：二分+贪心法，$O(nlog\ n)$

1. 使用一个辅助数组`tails`，其中`tails[i]`表示长度为i+1的递增子序列的最小结尾值

2. 遍历输入序列`nums`，对于每个元素：
   - 如果`nums[i]`比`tails`的所有值都大，则将其添加到`tails`的末尾
   - 否则，用二分查找找到第一个大于等于`nums[i]`的位置，并用`nums[i]`替换这个位置的值
3. `tails`的长度即为最长递增子序列的长度

伪代码：


    function LIS(nums):
        tails = []
        
        for num in nums:
            pos = binarySearch(tails, num)
            if pos == len(tails):
                tails.append(num)
            else:
                tails[pos] = num
    
        return len(tails)
    
    function binarySearch(tails, target):
        left, right = 0, len(tails) - 1
        while left <= right:
            mid = (left + right) // 2
            if tails[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
        return left
